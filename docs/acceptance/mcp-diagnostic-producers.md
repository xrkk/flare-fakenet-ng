# MCP diagnostic source candidate and retained acceptance gaps

The required terminal scope remains native crash, unavailable stacks, and
unknown cause. Native crash and the explicitly scoped no-stack path have
source candidates validated only across controlled OS/SDK fixtures. Legacy unknown requests remain blocked; a separately versioned explicit diagnostic context selects the controlled self-exit source candidate. None has a
complete native pass; the full 62 required cases / 9 implementation items /
14 acceptance items remain incomplete.

## Explicit no-stack contract

The controller introduced the narrowly scoped contract
`FN-REGRESSION-DIAGNOSTIC-STACKS-01` after its author self-review. Ordinary
packages and every other fault retain the default complete/basic predicates.
The original collector, preparer, supervisor and exit monitor are unchanged.

The source candidate binds a plan to the actual service birth, child birth,
Job, run, locked configuration hash, nonce and bounded expiry. The child is
armed before its first stack snapshot. A fixed transparent fail-fast then
creates a terminal event; it is not mislabeled as an unknown cause. Existing
stack files are preserved and block no-stack credit. The supervisor resets
its previous stack observation at run start; the pinned original preparation
chain must actually produce the unavailable item when no fallback works.

The original ZIP must still contain exactly the honest manifest failure
`thread_stacks.txt / failed / unavailable / size=0 / sha256=null`, and must
omit that member. Raw manifest and exported `complete` remain false; original
failure reasons remain visible. A separate `diagnostic_assessment` describes
whether that precise failure was expected. Its presence grants no credit.

The exporter, round validator, ReleaseGate fault consumer, P04 consumer and
independent selected-unit oracle each reread original bytes. All other basic
members, configuration bytes, dump PID, exit identity/code, original transfer
hash and bounded ZIP expansion still have to match. Typed window/trigger
sidecars and fallback absence observations must agree with the original
transport paths/responses. Wrong nonce/birth/config/Job/window, existing
fallback, missing dump, budget error, corrupt other member or failed recovery
prevents a pass. Without explicit structured evidence the default validator
continues to reject the incomplete package.

The actual startup chain passes a locked configuration path outside the run
directory. The candidate checks that real absolute source and content hash;
it no longer incorrectly requires the input to be a run-local file. The
original run evidence still supplies the independently checked config copy.
This is a static correction, not an observed Windows execution result.

## Explicit unknown diagnostic domain

`fakenet.unknown-self-exit.v1` opts in only to the selected unknown diagnostic
unit. It fixes ExitProcess to the current verified child and code 0xE0420001,
behind the existing environment and typed run/birth/Job/config/window arm.
The trigger is transparent test truth, separate from product exception bytes.
Legacy arms, normal and disabled operation keep their previous behavior.

The original fault consumer waits for terminal failure before protective
convergence. The independent oracle rereads every complete declared basic
member and checks its manifest hash/size, full UTF-8/JSON diagnostics, original
self-exit notification, empty terminal Job, dump target, target birth, original
transport and owned service/config/environment recovery. Known application
errors, explicit error/exception/cause fields, emitted exception stacks,
unavailable or malformed domain members, normal acknowledgments and external
termination refuse unknown credit. The declared symptoms `managed process
exited` and `managed IPC EOF` are not application causes. The assessment pins
every examined member and does not change raw exit classification or manifest
completeness. Unfamiliar diagnostics conservatively refuse classification.

Controlled OS/SDK fixtures exercise original producer, child hook, fault
consumer, exporter, byte validators and central execute/judge. They cannot
establish real Windows monitor/Job/dump behavior or full ACC-014. The original
five-class matrix and independent package-only localization remain required.
