## 1. 使用哪一个入口

本说明使用 **Windows MCP 主管服务**：通过 `load_config`、`start`、`stop` 管理 FakeNet。当前 ZIP 中的入口是 `fakenetng-mcp.exe`，不是 GUI 包；GUI、核心直接运行和 MCP 主管不要同时接管同一台机器。

```text
ZIP SHA-256: cb01772f49be8539280776a0cec6ebc3916b8fee5e53529f1584aaef40adedb1
EXE SHA-256: 8d6d1ece9c68b3ea3289a70f7fe7822d50f4a3d2536610b02ccaf7f4f98fd6db
```

2026-10-06 已在宿主重新核对 ZIP、清单封套和全部 199 个 payload 的大小与 SHA。未因此重新构建、安装或核实当前来宾部署；包及宿主核验记录见 [离线库存](../Logs/actual-use-transition-20261006/offline-inventory.json)。

优先沿用已部署的同一候选。首次连接核对实际安装身份、工具列表与服务状态，避免因仓库 HEAD 变化而无意义地重新安装；最近的验收工具提交没有改变产品。

## 2. 首次连接与必要准备

项目最后核对的实际 VM 是 `DESKTOP-3FI41GR`，MAC `00-0C-29-C1-CA-49`，BIOS UUID `D9FD4D56-3DC4-C64B-19F1-411EEBC1CA49`。历史产品地址为 `http://192.168.204.233:28788/mcp`；`28787` 是独立的 VM 管理端点。地址和在线状态须在使用时重新核对。

1. 确认目标 VM、现有服务安装路径、候选身份和本次分析输入。先保留可能尚未导出的来宾文件，再决定是否需要环境恢复。不要套用其他 VM 的快照或电源指令。
2. 服务只绑定专用 host-only 地址，防火墙来源限制为指定宿主。本产品当前明文 HTTP 部署合同适用于该隔离网络。
3. 客户端连接 `/mcp`，先只读调用 `tools/list`、`ping`、`get_status`。核对实际 schema；状态中的 run、controller、恢复责任及进行中的命令必须明确，再开始自己的工作。
4. 保留一个本次控制者 UUID，通过 `X-FakeNet-Controller-ID` header 发送。它是协作身份，不能用来覆盖其他控制者的责任。
5. 核对来宾数据卷和宿主回传目录的剩余空间，明确本次预计时长、日志/PCAP开销及停止条件。只采集分析需要的产物，停止后再封存和传回。

原正式验收的 24 GiB 宿主保留线及全套复制预算仍适用于正式 runner；日常运行的实际存储需求需按本次采集和回传测量。不能把正式单场的约 33.7 GiB 直接当成 MCP 核心启动需求，也不能未经测量断言当前容量足够。

现代协议 header（值取自当前产品实现）为：

```text
Content-Type: application/json
Accept: application/json, text/event-stream
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: <本次工具名>
X-FakeNet-Controller-ID: <本次固定控制者UUID>
```

默认现代模式不先发传统 `initialize`，没有额外 GET SSE 端点。需要旧式握手的客户端，应按既有 `allow_legacy_protocol` 配置合同选择兼容模式，不能遇到连接错误就自动修改服务。
现代协议调用不先发传统 `initialize`，没有额外 GET SSE 端点。2026-10-06 起源码默认 `allow_legacy_protocol=true`，兼容 Codex 等需要初始化握手的客户端；已有安装显式 `false` 仍生效，需在 service.json 中改为 `true` 并受控重启服务。旧 ZIP 的源码身份和默认值保持原样。

## 3. 一次实际分析的操作顺序

| 操作 | 应确认的结果 |
| --- | --- |
| `list_configs`、`read_config` | 选定现有配置，保存配置名与原字节 SHA。需要新配置时创建独立自定义 INI，不覆盖内置文件 |
| `validate_config` | 配置语法与基本语义有效；具体网络、路由和监听器可用性仍由运行时检查 |
| `get_status` → `load_config` | 使用刚取得的 `state_version` 和新的 `command_id`；之后核对 `config_identity` 与预期 SHA |
| `start` | 使用新版本及新命令 ID；核最终 `healthy`、具体 health 内容，保存真实 `run_id` |
| 执行真实分析工作 | 观察目标程序的实际网络行为；按需要读状态和事件，不启动场景矩阵、Spike 或压力循环 |
| `stop` | 等待停止和恢复终态，核 `stopped`、run/controller 及恢复诊断；上次运行失败须如实保留 |
| `list_artifacts` | 仅选本次 run 的产物，等待 `complete=true`，记录 size/SHA 后再传输和打开 |

普通停止使用 **MCP 工具 `stop`**。服务 CLI `fakenetng-mcp.exe stop` 是服务级受控退出，用于维护；停止核心不等于停止或卸载主管服务。

各变更必须携带实际 `expected_state_version`。可以沿用已成功响应返回的新版本；版本冲突时只读重新判断，不盲重试。配置编辑还需 `read_config` 返回的 `expected_sha256`。

遇超时或断连，保存原控制者、`command_id` 和请求，先只读核状态/事件并对账。当前产品没有独立 `resolve_command` 接口。只有确认同一服务实例且为完全相同的请求时，才按既有幂等合同使用原 ID；不要以新 ID 重发未知结果的变更，服务重启后也不能假定内存命令缓存仍在。

## 4. 产物保存和结束

MCP 数据默认位于 `%ProgramData%\FakeNet-NG-MCP`：服务日志在 `logs\service.log`，配置审计在 `logs\config-audit.jsonl`，自定义配置在 `configs\custom`，分析产物在 `artifacts` 下的实际 run 目录。安装目录 `configs` 保存内置配置。

`list_artifacts` 返回的是受管文件元数据，不提供文件正文下载；当前接口也没有 `run_id` 过滤、分页或摘要参数。调用者按真实 run/路径选择，不能将诊断超时的空数组当成没有产物。

回传到宿主仓库 `Logs/actual-use/<本次唯一目录>/`；通过已授权 host-only 通道传输，校验 SHA，传输结束停止临时服务。`dist/` 只保存分发包。保持已有恢复/基线和历史原件完整；清理先审计准确清单，不按年龄或目录通配删除。

## 5. 发现问题时提供这些信息

每个真实问题独立记录，放在本次运行目录的 `issue.md`，无需先扩展测试框架：

```text
现象、预期行为、首次发生时间（含时区）：
使用包/源码、EXE SHA、目标 VM/服务实例：
配置名与 SHA、控制者、run_id、command_id：
最短操作顺序、原请求、原响应或错误：
问题发生前后 get_status/get_events：
关联日志/PCAP/报告路径、大小、SHA：
停止/恢复是否完成，是否仍有责任或未知结果：
对本次分析的影响、是否可重复、临时处置：
```

影响启动、控制通道、正确流量处理、停止恢复或数据保存的真实问题优先处理；响应体积和便捷接口按实际影响排序。修复前用本次原件定位，修复后仅验证受影响功能和必要反例，再继续实际工作。产品/包装有变化时生成新候选并记录部署身份；保存失败原件，不拼接正式验收信用。

若 `failed/recovering/needs_recovery` 或停止结果未知，先保全现场和原责任；不删除恢复文件、不强制把状态改成 stopped，也不直接启动第二个核心实例。

## 6. 确实需要安装时

在目标 Windows 的管理员 PowerShell 中，从完整解压后的同一包目录运行安装脚本，提供实际 host-only 地址和允许宿主 IP；例如参数名为 `-ListenIp`、`-Port`、`-AllowedHost`、可选 `-ExtraExcludePort`。安装会替换服务注册，已有部署正常时不重复安装。

随后使用 `fakenetng-mcp.exe start` 启动主管服务，再按上面的 MCP 流程操作核心。当前 `extra_control_ports` 能排除控制流量被 WinDivert 接管，但不会自动为额外端口建立完整入站防火墙规则；28787 等独立管理通道的规则和可达性应另核，不能将排除配置等同于防火墙已放行。
