(错误修复)

本轮 v33 实机问题的规范性边界补充如下:

1. GUI 的“停止”必须完成真实会话的优雅关闭, 包括 listener, Diverter, PCAP, 报告和网络状态恢复; 只写入 stop flag, 只打印 `Stopping...`, 或最终强制结束进程都不算成功.
2. “将其他域名导向私网分析主机”中的 `192.168.204.1` 是 Ubuntu 私网分析主机的真实终点. Windows VM 发往该精确地址的 TCP 和 UDP 流量必须保留原协议和原目标端口到达 Ubuntu, 不得改写到 Windows 本机 FakeNet listener.
3. Ubuntu 终点不可达时不得 fallback 到 Windows 本机 listener, 也不得把“DNS 已返回 `192.168.204.1`”当作通信验收通过. 验收必须有 Ubuntu 主机收到同一 nonce 的 TCP/UDP 日志证据.
4. Windows VM 的一键验收在需要人工配合时, 必须在控制台明确打印用户要做的唯一步操作, 当前等待状态, 失败原因, 下一步和证据绝对路径; 不得让用户自己猜脚本顺序或复制多条 Windows 命令.
5. Ubuntu 侧唯一必要的人工动作是运行仓库根目录的 `Start-FNPR-Sentinel.sh` 并保持窗口打开, 待 Windows VM 一键验收明确提示后再按 Ctrl+C 停止. 工具只做只读地址/端口前置检查, 不自动修改 Ubuntu 地址, 路由或防火墙.
6. 手工 GUI 复现的一键证据导出必须包含当次 GUI 日志, 核心日志, 实际启动的 INI 副本及 SHA-256, PCAP, 报告和停止阶段标记; 缺少当次 INI 时不得归因 GUI 配置链.
7. 停止反馈和总退出耗时按以下统一合同验收:
   - 计时起点为 GUI 停止回调接收用户点击的单调时钟时刻; GUI 必须在 1.0 秒内显示明确的“正在停止”状态.
   - 完整策略会话必须在同一起点后 5.0 秒内使 GUI 持有的 Windows `fakenet.exe` 顶层进程句柄返回, 且退出码为 0.
   - 每次验收均必须同时完成 listener, Diverter, PCAP, 报告、DNS/适配器网络状态恢复; 耗时达标不得取代这些正确性条件.
   - 在同一隔离 Windows VM 快照基线上执行 3 次互相独立的完整策略会话, 3 次全部同时满足 1.0 秒反馈、5.0 秒退出和全部正确性条件才算通过.
   - 不得使用强制结束进程、提前解锁 GUI、提前关闭进程句柄、忽略非零退出、吞掉清理错误或缩减必需产物来达到时限.
