## 1. 意见清单

### B-01【中等】§4 判定表存在未覆盖的观测组合："C=立即返回但内容为空"无裁定

**引用章节**：方案 §3 步骤 C、§4 判定表（第一、二行）。

**证据**：步骤 C 的判据为"立即返回且内容非空 ⇒ 假说坐实；阻塞等待键击 ⇒ 残留不存在"。但若缓冲残留是**换行类字符**（'\r' 或 '\r\n'——用户按下的回车键残留正是此类，也是"需要额外一次回车"现象最可能的残留形态），`input('X')` 的行为是**立即返回空字符串**：既不落入"立即返回且内容非空"，也不落入"阻塞等待"。判定表对"B=需第二次回车 且 C=立即返回空"的组合**没有裁定行**。

**影响**：真实复现场景中最可能的观测结果（残留为回车）恰好落在判定表的空隙里，复现协议无法机械闭合——与方案"机械闭合，无并列方向"（§4 标题）的承诺不符。若按字面执行，操作者在该观测下既不能实施 R1（不满足坐实条件）也不能关闭/回流（不满足否定条件），方案流程卡死。

**建议修改**：把步骤 C 的判定改为"**立即返回（无论返回内容是否为空）⇒ 残留存在，假说坐实方向成立**；阻塞等待 ⇒ 残留不存在"，并同步改写 §4 判定表（"C=立即返回"取代"C=立即返回非空"）；或在判定表显式增加一行："B=需第二次回车 且 C=立即返回空 ⇒ 假说坐实，实施 R1"。

### B-02【轻微】§3 步骤 C"进程退出后同一控制台立即执行"依赖人工时序，存在假阴性窗口

**引用章节**：方案 §3 步骤 C、§6 验收"随后同控制台立即执行 C 探针"。

**证据**：conhost 输入缓冲按控制台归属、进程退出不清空的假设本身成立，但步骤 C 的执行时机由操作者手动控制（键入命令需要时间），且若残留缓冲在 fakenet 退出后被任何后续按键消费（如操作者误按方向键/回车），探针将表现为"阻塞等待"而假阴性；§4 第二行会把这种假阴性裁定为"假说否定、另立根因调查"，产生错误分流。方案已用 cmd/PowerShell 双轮与 `cls` 重置缓解，但未要求记录"进程退出到探针执行之间的时延"或给出假阴性判定时限。

**影响**：低——双轮与人工记录可部分兜底；但"假说否定"分支会导致方案关闭（不实施）或错误另立调查，误判成本存在。

**建议修改**：步骤 C 记录项增加"进程退出→探针执行的时延"（秒级即可）；并在 §4 裁定说明中注明：若 B 复现（需第二次回车）而 C 阻塞，须在**重置后的新一轮**中先做一次"无残留对照"（新控制台直接跑 C 探针应为阻塞），以排除探针本身与时机因素。

## 4. 审计结论（独立意见）

### 4.1 根因证据是否坐实

**未坐实**（方案自身如实声明）：缓冲残留假说当前仅有代码层旁证（唯一 input 点、静态只能解释一次回车）与用户口头报告，机制未证实。方案以"实机复现前置"处理，且为假说否定/不可复现预设了关闭或回流路径——这是对"根因未坐实"的正确处置，没有把假说冒充结论。

### 4.2 双向追溯与验收契约

闭环成立：需求 → 复现协议 → 判定表 → 修法 → 验收相互引用，无无落点条目；验收（§6）的修复前基线、通过判据、FAIL 边界与回流路径机械可执行（B-01 修正后）。GUI 路径归母方案 I2/M1①，与母方案无重叠无遗漏。

### 4.3 修复是否直达根因与回归是否充分

R1 直接针对假定根因（缓冲残留）排空，不绕过、不屏蔽；若假说被否定则禁止实施——不存在"在外围叠加甲"的问题。回归分宿主（全量 + R1 单测）与 VM 手测（同路径 A/B/C），能证明修复前后行为变化，并含 `-p` 路径与 Linux 无破坏确认。

### 4.4 结论

**存在不同意见，需处理审计结果。** 需处理项：B-01（中等，判定表补"立即返回空 ⇒ 坐实"或改"立即返回"判据）、B-02（轻微，记录时延并补对照步骤）。处理方式为升版（v0.1）后复审；按方案自身门禁，§3 复现协议与 §4 判定表修正不影响"复现前置"性质，修法 R1 与验收路径无需改动。
