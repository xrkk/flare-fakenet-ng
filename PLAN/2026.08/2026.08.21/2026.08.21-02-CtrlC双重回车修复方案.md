## 0. 生效约定

沿用母方案 §0 全部门禁（宿主禁跑核心、包不可覆盖、回归命令、Write/Edit 落盘、提交风格）。本方案不产出新构建包——修复随母方案之后的首个构建批交付（若母方案已实施完毕，则随其下一升版包；两者不得挤入同一未审核批次）。

## 1. 现象与证据分级

**现象**：手动控制台运行 fakenet（不带 `-p`），Ctrl+C 触发清理，打印 `[Press Enter to exit]` 后，用户需按两次回车进程才退出。

**已证实**（代码直读，@30e1a75）：
- `fakenet/fakenet.py:715` 为全库唯一 `input("[Press Enter to exit]")`（Start 脚本路径除外）；`Start-EgressControl.ps1` 路径带 `-p` 且隐藏窗口，无控制台可 Ctrl+C，排除。
- 静态代码只能解释**一次**回车（main() finally 单次 input → sys.exit）。

**未坐实假说（本方案的核心待证命题）**：Windows conhost 的控制台输入缓冲残留——Ctrl+C 处理/清理期间（或键入 Ctrl+C 时伴随的字符事件）滞留输入队列，`input()` 先消费残留再等待换行，表现为需要额外一次回车。宿主为 Git Bash/MinTTY，**无法**复现 VM conhost 的键序，故必须实机复现前置。

## 2. 需求与目标行为

- 需求：手动控制台路径下，Ctrl+C 清理完成后，**恰好一次回车**进程即退出。
- 目标行为仅在假说坐实后按 §4 判定表实施；假说被否定或无法复现时，本方案不实施任何代码修改（处理路径见判定表）。

## 3. 复现协议（前置门禁；在 VM 上执行，实施任何修复前完成）

前置：隔离 VM；v32 或当前已交付包（不得为复现改动任何包内容）；控制台会话（cmd/PowerShell 均执行一遍，两者行为分别记录）。fakenet 以 `fakenet.exe -c <ini>`（无 `-p`）启动，配置任选（能产生 PCAP_DUAL_SUMMARY 的常规配置即可）。

操作与观测（逐步记录，证据=逐项文字记录+截图）：

- **步骤 A**：运行中按**一次** Ctrl+C。记录：① KeyboardInterrupt 到 `[Press Enter to exit]` 打印之间的时延量级与期间是否打印清理日志；② 此期间操作者**未敲击任何其他键**（人为保证，记录之）。
- **步骤 B**：提示出现后按**一次**回车。记录进程是否退出（区分：退出 / 无反应需第二次回车）。B=需第二次回车即现象复现。
- **步骤 C（残留探针，判定假说；B-01/B-02 修正判据）**：无论 B 结果如何，在 fakenet 进程退出后**同一控制台**立即执行：
  `python -c "print(repr(input('X')))"`
  记录三项：①该 input 是否**未等键击立即返回**（**无论返回内容空或非空**——残留为回车键时 `input()` 立即返回空字符串，同样证明残留存在，此为现象最可能的残留形态）；②返回内容（repr）；③fakenet 进程退出→探针执行之间的时延（秒级量级即可）。
  判据：**立即返回（空或非空）⇒ 控制台输入缓冲存在跨进程残留，假说坐实方向成立；阻塞等待键击 ⇒ 本轮未观测到残留**。
  （cmd 与 PowerShell 各执行一轮 A/B/C；每轮之间用 `cls`/新控制台重置，避免上一轮污染。）

## 4. 判定表（机械闭合，无并列方向）

| 复现观测 | 裁定 | 动作 |
|---|---|---|
| 任一控制台类型中 B=需第二次回车 **且** 同轮 C=立即返回（空或非空均可） | 假说坐实 | 实施修法 R1（§5）；实施后按 §6 验收 |
| B=需第二次回车 但 C=阻塞等待 | 假说否定（**须先过无残留对照**，B-02） | 对照步骤：重置后的**新控制台**直接执行 C 探针，应为阻塞等待——若新控制台探针即已立即返回，说明探针/环境本身有残留噪声，本轮 C 观测无效，重置后重跑完整复现轮；对照成立（新控制台阻塞）方可裁定假说否定，**禁止实施 R1**，停止并回流：本方案升版，附复现记录，另立根因调查（候选方向如二次 Ctrl+C 事件、控制台模式切换，须以新证据立项，本文不预设） |
| B=单次回车即退出（两种控制台类型均无法复现） | 现象不可复现 | 记录后关闭本方案（不实施任何修改）；用户后续复报时凭新现象重新立项，原记录作为基线 |

## 5. 修法 R1（仅在 §4 第一行裁定成立时实施）

- **允许修改**：`fakenet/fakenet.py`（main() finally，:715 `input("[Press Enter to exit]")` 之前）；新增/调整对应宿主单测。
- **目标行为**：`input()` 调用前，Windows 平台排空控制台输入缓冲，代码逐字采用：
  ```python
  if os.name == 'nt':
      try:
          import msvcrt
          while msvcrt.kbhit():
              msvcrt.getwch()
      except Exception:
          pass
  ```
  非 Windows 平台与 `-p` 路径不执行任何额外动作（`options.no_pause` 分支不进入该代码）。`getwch` 天然吞掉方向键等功能键的双字节前缀，无需额外处理。
- **前置**：§3 复现记录 + §4 第一行裁定，缺一不可。
- **实施者可裁决**：无（代码逐字采用）；单测组织方式可自定（建议 monkeypatch `msvcrt.kbhit/getwch` 序列断言排空与非 Windows 短路）。
- **回流边界**：R1 实施后 §6 验收仍需两次回车 ⇒ 假说虽坐实但修法不足，停止并回流升版本方案。
- **验收**：见 §6。

## 6. 验收契约

- **修复前基线（=§3 复现记录）**：A/B/C 三步逐项记录在案（B=需第二次回车、C=立即返回（空或非空均可，B-01 判据））。
- **宿主回归**：§0 门禁全量回归通过数不低于母方案记录的基线；新增 R1 单测通过。
- **VM 手测（修法实施后，证据=记录+截图）**：与 §3 同一操作路径（同控制台类型、同配置）执行 A/B：**B=单次回车即退出**为通过；随后同控制台立即执行 C 探针：**阻塞等待键击**（无残留）为通过。任一不满足即 FAIL，走 §5 回流边界。
- **无破坏确认**：`-p` 路径（GUI 启动与 Start 脚本）行为不变（无暂停、无报错）；非 Windows 平台启动冒烟不变（宿主单测覆盖）。

## 7. 实施阻碍

- **HB1**：复现协议（§3）必须由用户在 VM 上人工执行（键击时序无法由分析机自动化），分析机不可代跑；无复现记录则本方案永不进入实施。
- **HB2**：`python -c` 探针依赖 VM 内 python 可用（包内验收 runner 所用解释器满足）；若目标控制台会话无法调用 python，改用任意可执行交互程序（如 `cmd /c set /p X=`）作为等价残留探针并在记录中注明替代命令。

## 8. 审核重点

1. §4 判定表三分支是否穷尽且互斥（复现+坐实 / 复现+否定 / 不可复现），是否还存在第四种观测组合需要补充裁定。
