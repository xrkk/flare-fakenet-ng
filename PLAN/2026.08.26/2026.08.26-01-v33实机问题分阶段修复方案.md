## 0. 方案目的与生效边界

本方案定位于 v33 VM 验收中已证实的现象、已证实的当前代码行为，以及待固化的目标行为。当前证据尚不支持把它们统称为“已定根因的三条故障链”：

1. **已证实现象**：GUI 点击“停止”后，停止旗标已到达核心，但该次完整策略会话未完成 Diverter、PCAP、报告和网络恢复的可观察关闭。阻塞点尚未缩小到单一调用点。
2. **已证实现象**：一次 GUI 手工会话加载了某用户 INI，却没有进入 takeover 模式。当次 INI 未随证据导出，所以尚不能确定是用户触发条件、GUI 控件、model、保存、重载还是启动绑定丢失了事实。
3. **已证实代码行为**：v33 有意将 takeover sink 流量 `DIVERT_FAKE` 到 Windows VM 本地 listener，而不是真实发向 Ubuntu。将终点改回 Ubuntu 是一项行为取代，不是未知根因的偶发 bug。
4. **已证实验收缺口**：现有测试分别覆盖内存控件或直接生成核心配置，没有覆盖“GUI 控件→保存→重载→核心启动”的完整 interface，且手工证据不包含当次 INI。

本方案不处理主动式架构治理候选项、Linux FakeNet 策略功能对等、多主机协调、自动故障转移、远程管理 Ubuntu、HTTPS 中间人、DoH 解密、多进程规则扩展或其他新增功能。不得借本方案清理无关旧代码。

本 v0.2 自评仍未通过，且 §2.4 列出了尚未闭合的高风险门禁。用户已授权执行用于闭合门禁的规范性来源补充和纯诊断取证工具，该授权不包括 IMP-002 至 IMP-006 的业务修复或 v34 交付。Windows FakeNet 核心和 WinDivert 只能在隔离 VM 中运行；Ubuntu 开发主机只能执行静态检查、平台无关测试和 Ubuntu Sentinel。

## 2. 固定行为与取代关系

### 2.1 私网接管唯一取代语义

1. `ExternalTakeoverIPv4=192.168.204.1` 的唯一权威含义是 Ubuntu 私网分析主机地址。
2. 非放行域名的 A 查询继续由 FakeNet DNS 合成 `192.168.204.1`；放行域名、通配域名及其真实出口语义不变。
3. Windows 样本发往精确 sink 的 TCP/UDP 数据包必须保留目标 `192.168.204.1`、原协议和原目标端口，经已验证的 on-link 路由真实发往 Ubuntu。
4. sink 包不得进入 Windows VM 的 `DIVERT_FAKE`、`maybe_redir_ip` 或本地 HTTP/Raw listener。Windows 本地 listener 仍用于普通未审核公网直连等既有 FakeNet 行为，不因本方案删除。
5. 仅精确 sink 可获得 `ALLOW_TAKEOVER_SINK`。其他 RFC1918 地址、公网地址、IPv6、路由漂移或策略挂起状态不得借该裁决放行。
6. Ubuntu listener 不可达时绝不回退到 Windows 本机 listener。运行器前置验收拒绝启动；生产配置若未启用可选端口探测，则连接按真实网络结果失败，不伪造本地成功。

SRC-REQ-003 明确取代 SRC-OLD-001 §2.6、I5 和 A11/P15 中“sink 在 VM 本机入彀”的部分，但仅取代 sink 终点语义和对应验收；SRC-OLD-001 的停止按钮、双向 PCAP、报告、普通 FakeNet listener 和其他已实施行为继续有效。

### 2.2 停止完成定义

“停止成功”必须同时满足：stopflag 被核心发现；策略挂起；所有 listener 停止；Diverter 停止；活动 relay/socket 关闭；WinDivert 和捕获线程退出；双 PCAP writer 关闭并输出健康汇总；报告生成；DNS/适配器状态恢复到启动前快照；核心记录 `rc=0` 并在现有 VM runner 已采用的 40 秒停止等待上限内退出。只写旗标、只显示 `Stopping...` 或 GUI 最终观察到进程消失均不构成成功。

GUI 不得在停止超时后自动 `taskkill` 并宣称成功，因为这会绕过网络恢复。超时进入 FB-003。

### 2.3 GUI 配置生效定义

用户启用接管、保存并启动后，同一份磁盘 INI 必须包含非空 `ExternalTakeoverIPv4` 及其配套字段，通过 validator，并由核心记录 `DOMAIN_TAKEOVER_READY`。GUI 必须在会话日志中记录配置绝对路径和 SHA-256，证据导出必须包含字节相同的 INI 副本。内存 model 断言、保存成功提示或直接由测试代码生成配置均不能替代该端到端判据。

- **操作**：VM 总入口先做 TCP/443 与 UDP/443 FNPR/1 前置，再查询非放行域名并通过该应答地址重复 TCP/UDP nonce；检查核心和 Ubuntu 日志。
- **精确结果**：DNS 只返回 `192.168.204.1`；VM 收到两个正确 nonce echo；Ubuntu 日志记录同 nonce 的 `transport=tcp` 和 `transport=udp`；核心记录对应 `ALLOW_TAKEOVER_SINK`；不得记录 `DIVERT_FAKE dst=192.168.204.1` 或 Windows 本地 listener 处理该 nonce。
- **证据**：Windows 结果 TSV/核心日志/PCAP、Ubuntu sentinel JSON 日志、nonce 对照。
- **通过边界**：只有 DNS 成功、只有 TCP、只有 VM 本地 HTTP 200、nonce 不一致或 Ubuntu 无日志均 FAIL。

### ACC-008 接管负向边界

- **对应 IMP**：IMP-004。
- **需求来源**：SRC-REQ-001、SRC-REQ-003。
- **前置与输入**：与 ACC-007 同会话；一个放行域名、一个非放行域名、一个 sink 邻接私网地址、一个未知公网 IPv4 和 IPv6。
- **操作**：执行现有 P 组加新增负向探针。
- **精确结果**：放行域名保持真实受控出口；非放行域名只指向 sink；邻接私网地址不能获得 `ALLOW_TAKEOVER_SINK`；未知公网仍按现有 Divert/Drop 合同；IPv6 仍 fail-closed。
- **证据**：policy-results.tsv、核心日志、PCAP。
- **通过边界**：接管 verdict 扩散到任一非精确目标或破坏既有放行域名链均 FAIL。

### ACC-009 一键交互、拒绝和证据导出

- **对应 IMP**：IMP-001、IMP-003、IMP-005。
- **需求来源**：SRC-REQ-004、SRC-OPS-001。
- **前置与输入**：第一次 Ubuntu sentinel 未启动，第二次正常启动。
- **操作**：双击 VM `Run-All-Tests.cmd` 各一次；第二次完成 A/P 与导出。
- **精确结果**：第一次在任何 WinDivert/DNS 修改前退出码 2，并打印唯一 Ubuntu 命令；第二次自动完成测试，最终打印总体结论、Windows 绝对证据目录、Ubuntu 日志模式、Ctrl+C 收尾提示。导出物包含本轮 INI 与 hash。
- **证据**：两次 console transcript、结果表、启动前后 DNS 快照、导出目录清单。
- **通过边界**：要求用户猜脚本顺序、复制粘贴多条 Windows 命令、前置失败后仍修改网络、未打印证据路径或缺配置均 FAIL。

### ACC-010 v34 全量门禁

- **对应 IMP**：IMP-006，并汇总 IMP-001 至 IMP-005。
- **需求来源**：SRC-REQ-001 至 SRC-REQ-004、SRC-OPS-001；SRC-REQ-005 不作为业务验收来源。

## 6. Fallback 契约

| Fallback ID | 依据 | 触发条件 | 影响 | 退出方式 |
|---|---|---|---|---|
| FB-001 Ubuntu Sentinel 前置拒绝 | SRC-REQ-003、SRC-REQ-004；接管无本地备用语义 | TCP 或 UDP FNPR/1 在 120 秒内未通过，或 `192.168.204.1` 非唯一绑定 | VM runner 以 REFUSED/2 退出；不得打开 WinDivert、改 DNS 或运行后续测试 | 在 Ubuntu 修复地址/权限/端口占用，重新运行唯一 `Start-FNPR-Sentinel.sh`，再双击 VM 总入口 |
| FB-002 sink 路由失效 | 既有 route guard 和 SRC-REQ-003 | 启动前 route identity 不满足 on-link，或运行中地址/路由漂移 | takeover 子状态 fail-closed；不改走默认网关、不改到 Windows listener | 保持 VM 隔离，恢复既定 host-only 网络或回滚快照，重新通过路由与 sentinel 前置 |
| FB-003 停止超时安全退出 | EV-STOP-002、SRC-REQ-002 | 停止请求后 40 秒仍未满足 §2.2 | GUI 标为 STOP_TIMEOUT，禁止再次启动；不自动 taskkill，不宣称网络已恢复 | 立即导出可取得证据，断开 VM 外部网络并回滚已知干净快照；将阶段日志回流本方案，不在污染状态继续验收 |
| FB-004 构建/验收环境缺失 | SRC-OPS-001 和 Windows-only WinDivert 约束 | Ubuntu 无法构建 Windows frozen 包，或 Windows 构建依赖不完整 | 不产生手工拼装 v34，不在 Ubuntu 运行核心 | 使用干净 Windows 构建环境按 ACC-010 构建；依赖仍缺失则记录精确缺项并停止，不下载未审核替代物 |

除表中四项外没有授权 fallback。尤其禁止 sink→Windows 本地 listener、TCP→仅 DNS 成功、UDP→TCP、优雅停止→自动强杀等降级。
