## 2. 自评发现与修正

### `SELF-001`

- 风险：中。
- 对应章节：方案 §2.1、§2.4、`ACC-002`、§11。
- 证据：初稿 `ACC-002` 直接使用镜像预装 pydivert 2.0.9，实测为 `1 failed, 70 passed in 2.10s`；失败点是该版本没有 `WinDivert.check_filter`。只读解包并挂载仓库固定 pydivert 2.1.0 后，身份探针为版本 2.1.0、`check_filter=True`，相同四个测试文件得到 `71 passed in 1.22s`。
- 问题和影响：原命令会把环境依赖错配误报成产品回归失败，实施者无法稳定执行验收合同。
- 修改：方案升至 v0.1，新增 `EVD-SPIKE-002`，把 `ACC-002` 固定为临时解包仓库 wheel、只读挂载并设置 Windows `PYTHONPATH` 的已验证命令；稳定 IMP/ACC ID 不变。

### `SELF-002`

- 风险：中。
- 对应章节：`ACC-001`～`ACC-008`。
- 证据：v0 各 ACC 有目标结果和失败边界，但没有逐项显式分开“修复前基线”与“修复后精确结果”。
- 问题和影响：第三方和实施者需要跨章节自行拼接前后事实，降低可复现性，也可能把旧基线能力误当本轮新增通过项。
- 修改：为全部 8 个 ACC 补齐修复前基线和修复后精确结果；`ACC-006` 明确 v35 测试总数会随新增测试改变，机械要求收集总数等于 PASS 加两个已证环境 SKIP，不把旧 525 固定成新总数。

### `SELF-003`

- 风险：中。
- 对应章节：方案 §7、`DEC-006`、`DEC-011`。
- 证据：v0 已允许 owner 为 `unknown`，也要求 fatal 时 GUI 打开证据目录，但 fallback 清单只列构建环境、`DumpPackets=No` 和无效 UTF-8。
- 问题和影响：已有合同没有完整进入 fallback 总表，审核者无法机械确认未知 owner 不会导致流遗漏、fatal 会话不会选择历史报告冒充成功。
- 修改：新增 `FB-004` 与 `FB-005`，分别固定 owner 解析失败和 fatal 会话诊断入口的依据、触发条件、影响与退出方式；二者均不降低 payload 完整性或生成成功报告。

### `SELF-004`

- 风险：低。
- 对应章节：方案 §2.4、§10。
- 证据：仓库绑定 wheel 已证明 `Param` 枚举、set/get API 和 length/time 上界测试；本作者会话没有真实 Windows VM，不能证明两个真实 handle 都能成功回读三项固定值。
- 问题和影响：若把真实 VM 成功回读写成已证事实，会混淆代码能力与运行能力。
- 修改：明确将真实 VM set/readback 标为待核实运行事实。该事实不改变修复方向：实现必须使用固定值并精确回读，失败按 `DEC-002` 终止，不允许临场换默认值或降级。

修正后没有遗留中/高风险自评发现，也没有规范性需求变化或需要用户裁决的分叉。
