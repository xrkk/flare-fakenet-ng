## 二、必须修正项(错误)

### P1(错误)dev 模式启动命令不可用 — §5.5 第 3 条
方案写 dev 态启动为 `[sys.executable, fakenet/fakenet.py]`。**该命令不成立**:`fakenet/fakenet.py:33` 首行即 `from fakenet import listeners`,以脚本方式运行时 `sys.path[0]` 是 `fakenet/` 包目录本身,`import fakenet` 解析失败(ModuleNotFoundError);若开发机/CI 曾 `pip install .`(CI build.yaml:36 即如此),则会静默 import 到 **site-packages 里的旧副本**,产生工作树与运行版本错配——这恰是方案 §7 R5 自己警惕的版本错配问题的开发态翻版。

**修正**:dev 态应改为 `[sys.executable, '-m', 'fakenet.fakenet']` 且 `cwd=仓库根`,与 `Start-DomainAllowList.ps1:286` 的项目先例一致。§9 F4 的 Linux 手动命令提示同理必须是 `-m fakenet.fakenet` 形式。

## 三、遗漏考虑项

### P2(中)写出编码策略未定义 — §5.2
方案定义了**读取**编码策略(utf-8-sig 优先、区域编码回退)和"非 ASCII 值保真保留(不转码)",但未定义**写出**编码,以下四点缺失将使"保真保留"无法精确落地、§6 断言无法写死:
1. 保存编码必须 = 读取时探测到的源编码(GBK 源写 GBK、utf-8-sig 源写 utf-8-sig),否则"不转码"无从谈起;
2. **BOM 保留策略**:utf-8-sig 读入的文件若存为无 BOM,属静默变更;且带 BOM 的文件被中文系统上的 fakenet 以 GBK 读时,BOM 三字节会混入首段名导致解析错乱——BOM 必须原样保留;
3. 新建文件的缺省写出编码未定(建议:纯 ASCII 内容,无 BOM,任一 ASCII 兼容编码皆可,但需定死一个);
4. 行尾风格(CRLF/LF)保真未提。

### P3(中)重复实例防护缺失 — §5.5
PowerShell 启动器有**独占锁文件**防止双实例(`Start-DomainAllowList.ps1:199-210`:双 WinDivert 句柄 + 双重 DNS 改写属未定义行为)。GUI 启动路径无任何等效防护:用户连点两次"▶ 启动"即拉起两个提权 fakenet 实例,且 GUI 无进程句柄可管(ShellExecuteW 不返回句柄)。**至少应**在启动前探测已运行的 fakenet.exe(`tasklist /FI`,标准库可用)并拒绝/警告。同时 §2 的"安全层差异清单"应把"无实例互斥、无文件日志留存(PS 版传 `-l` 落盘)"补入,目前只列了 3 项。

### P4(低-中)缺"已启用监听器 (Protocol, Port) 重复绑定"校验 — §5.3 规则 2
规则 2 只查段名/端口展开名冲突。两个**已启用**监听器同协议同端口时,运行时第二个 bind 失败(非 policy 模式仅记错继续,fakenet.py:266-269,行为半瘫)。应补:展开后启用段间 (protocol, port) 去重。

### P5(低)schema 完备性存在"代码有、模板无"盲区 — §5.1/§6
test_gui_schema 以"8 个 INI 的每个键"为完备性锚,以下键在代码中实现但不在(或仅注释于)任何模板,会漏网,与"原版全量暴露"目标不符:
- `BlackListIDsICMP`(`diverterbase.py:577` idlists 声明、`:1350-1354` 实际使用;default.ini:158 仅注释样例)——未列入 §5.1 六组任何一组;
- `cert_dir`(UseSSL 动态证书目录,`HTTPListener.py:217`、`listeners/ssl_utils/__init__.py`);
- DNSListener `ResponseA` 的特殊取值 `GetFirstNonLoopback`(domain_allowlist_windows.ini:85)——schema 需按"字面 IPv4 ∪ 特殊枚举"双态定义,方案未提;
- 测试措辞:第 8 个 INI 是 `sample_custom_response.ini`(自定义响应样例,段语义不是监听器),需按主配置/自定义响应两套 schema 分别断言,§6 未区分。

### P6(低)ShellExecuteW 返回值处理未提 — §5.5 第 4 条
用户取消 UAC 时返回 `SE_ERR_ACCESSDENIED(5)`(≤32 为失败),成功 >32。不检查返回值会在用户取消后仍提示"已启动"。

### P7(低)VM 检测在 UI 线程执行会冻结界面 — §5.5 第 2 条
CIM 查询秒级耗时,须在后台线程执行并处理超时;§5.4/§5.5 均未提线程化要求。(实现细节级,但建议写入方案防走样。)

### P9(低)`-c "<路径>"` 尾反斜杠边角 — §5.5 第 3 条
CommandLineToArgvW 语义下"结尾反斜杠 + 闭引号"会把引号转义为字面量。配置是文件路径通常无尾反斜杠,风险极低,但注入拒绝规则可零成本加一条"路径不得以反斜杠结尾"。

### P10(低)B2 门禁不完整 — §5.6
`continue-on-error` 只隔离构建 step;其后的**拷贝 step**(产物入 `fakenet_release\` 与 zip)在构建失败时同样会失败,也需同门禁(`if: steps.<build>.outcome == 'success'`)或一并 continue-on-error。zip 缺 GUI exe 本身可接受(F7 兜底),但 CI 不应因拷贝步骤额外飘红。

### P11(低)F7 持久化与保存路径的存储位置未定义
"手工指定 fakenet.exe 路径(持久化)"存哪里、什么格式(`%APPDATA%\fakenet-config\settings.json`?)未写。另建议:持久化路径无效时**回落**同目录探测并提示,否则用户误选一次后即使旁边就有正确 exe 也永不探测(v0.1 的"优先于同目录探测"表述过强)。

### P12(低)冻结态模板清单与 zip 实际内容不符 — §5.4
§5.4 列 7 个模板,但 release zip **剔除 burp.ini 和 debug.ini**(build.yaml:50)。冻结态"exe 旁 configs\"实际只有 5 个。模板菜单应改为枚举目录动态生成而非硬编码清单,缺失项不渲染。

## 八、方案方回应(2026-08-14,v0.2 裁决记录)

方案方按"不轻信"原则对审计全部承重论断做了**独立源码复核**,处理结果如下。

### 8.1 采纳(已引入方案 v0.2)
**P1–P12、F1(fail-closed)、§五 DoD 建议——全部采纳。** 独立复核锚点(均实地验证与审计一致):`fakenet/fakenet.py:33`(`from fakenet import listeners`)、`Start-DomainAllowList.ps1:199-210`(独占锁文件 FileShare::None)、`:286-287`(`-m fakenet.fakenet` + `-l` 日志参数)、`fakenet/configs/default.ini:158`(BlackListIDsICMP 仅注释样例)、`domain_allowlist_windows.ini:85`(GetFirstNonLoopback)、`HTTPListener.py:217`(cert_dir)、`DNSListener.py:224,232`(特殊枚举)、`build.yaml:49-50`(仅剔除 burp/debug)。F1 采纳理由:与全仓 fail-closed 姿态对齐;WMI 损坏场景下 PS 启动器同样依赖 CIM(`Start-*.ps1:720-724`)而一并失败,不产生 GUI 可用性倒退,fail-closed 无实际代价。

### 8.2 驳斥(部分):P4 的行为描述与源码相反
**采纳 P4 的校验建议,但驳斥其论据。** 审计称重复绑定后果为"运行时第二个 bind 失败(非 policy 模式仅记错继续,fakenet.py:266-269,行为半瘫)"。**独立复核源码 `fakenet/fakenet.py:265-274`,实际行为是 fail-fast 而非"记错继续"**:

```python
if not self.policy_mode:
    try:
        listener_provider_instance.start()
    except Exception as e:
        self.logger.error('Error starting %s listener on port %s:', ...)
        self.logger.error(" %s" % e)
        sys.exit(1)          # ← 整个进程退出,不是"半瘫"
```

即:同 (Protocol, Port) 双绑定时,第二个监听器 bind 失败会使 **fakenet 整体 `sys.exit(1)` 退出**——比审计所述后果**更严重**,因此前置去重校验的必要性不降反升(结论不受影响,论据必须纠正;方案 v0.2 §5.3 规则 2 已按纠正后的事实表述)。

### 8.3 口径澄清(部分):P12 的"冻结态实际只有 5 个"计数
**采纳动态枚举建议,但澄清计数口径。** `build.yaml:49-50` 仅剔除 burp.ini、debug.ini,冻结态 `configs\` 实存 **6 个 INI**(default + 4 个功能模板 + `sample_custom_response.ini`)。"只有 5 个"仅在"主配置模板"口径下成立。方案 v0.2 按"动态枚举 + **排除 `sample_custom_response.ini`**"落地,并补充审计未提及的依据:该文件 `[Example*]` 段**没有 Enabled 键**,误作主配置模板载入会被 fakenet 当作监听器段、在 `getboolean(section,'enabled')` 处直接抛 NoOptionError 崩溃(fakenet.py:108)——排除它是**正确性要求**,不仅是清单数量问题。

### 8.4 编号说明
审计编号自 P7 直接跳至 P9,无 P8,疑为审方删稿后未重排;无对应内容,不影响裁决完整性。

### 8.5 裁决结果
审计 12 项编号意见:11 项全额采纳,1 项(P4)采纳结论/驳斥论据,1 项(P12)采纳建议/澄清口径;F1 裁决采纳。方案已修订为 **v0.2**,无遗留分歧。
