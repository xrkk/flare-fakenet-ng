## 2. 四项定向复审结果

### PC006-R01｜发起者数据范围：闭合

总纲 §18.4 只接收和保存 Windows 已给出的 `%e/%i/%t/%c` 四个整数，明确禁止本新增助手为调查发起来源而打开、查询或保存其他进程的映像、创建时间、命令行、内存和 dump。`%e == %i` 时该 PID 仍是经过 run/PID/创建时间/绝对映像/命令行核验的受管目标，允许按既有条件式规则采集目标本身，不把“禁止发起者采集”误写成“禁止自行退出目标采集”。

外部终止的包内结论被限定为“系统报告某 PID/TID 跨进程终止同一受管目标，随后撤销健康并保护性恢复”，不声称查明发起方内部动机或具体模块；如果该因果范围不能满足记录 035 的包内定位门槛，必须停止并请用户重新裁决，而不是暗中扩大采集。用户限定、根因要求和失效出口现在一致。

### PC006-R02｜按映像名触发的资源边界：闭合

P01 改为只登记独立随包受管映像 `fakenetng-mcp-managed.exe`；主管/CLI `fakenetng-mcp.exe` 和助手自身均不登记，受管映像也不提供 CLI 服务命令。该设计先移除了产品正常主管/CLI 退出造成的系统性误触发，又保留对其他路径同名程序仍可能按名触发的真实限制。

助手进入口后先取得机器级单飞，最多一个执行者、不排队；busy/错身份/无当前 run 在 1 秒内拒绝，零持久文件/日志，不新建 run 目录，固定内存计数不超过 4 KiB。全局活动临时/拒绝诊断占用不超过 512 MiB，最终 incident 另受原 512 MiB 上限，不能删除历史证据腾空间；超时须释放单飞、句柄、锁和临时文件。

规范没有虚假声称能在助手代码进入口前限制 Windows 的瞬时进程创建。P05 必须在同名程序和突发退出负载下测全过程助手数量、生命周期、资源峰值及最终归零；若 OS 按名启动本身造成目标部署无法满足有界/清理条件，选型失败并重新裁决。原型 09/10 的 `UseFilter/FilterFullPath` 路径没有通知成功，现稿明确不采用，也没有把它变成隐藏 fallback。

### PC006-R03｜目标句柄所有权和结束门：闭合

P03 从受管进程创建开始独立拥有并保留目标句柄；poll 发现退出、Job 成员变空或 Python 包装释放均不得提前关闭。终止性退出先撤销健康，在同一 60 秒截止内等待 P04 助手取得同 run/同创建时间目标句柄的原子确认，并等待最终成功、明确失败或硬超时且助手已结束，之后才释放主管句柄；助手自行释放其句柄。

该等待不持停止编排锁、不阻塞 HTTP、不阻止进程结束，也不让 Job 终止依赖句柄释放。助手缺失/失败仍有明确结束，采集失败继续原 Job/补偿/全审计。P05 覆盖正常保留、过早关闭、PID 复用、迟到、助手失败以及主管异常退出的既有 Job+SCM 路径，已经把原型成功所依赖的句柄生命周期转化为产品可证伪合同。

### PC006-R04｜正常零退出授权：闭合

P03 在当前串行停止 attempt 内、发送受管 IPC stop 前，原子发布并读回确认一次性 stop intent。intent 绑定 run、目标 PID/创建 FILETIME、主管 PID/创建时间/实例随机 ID、stop attempt/单调序号、随机 nonce、发布时间和不超过优雅停止截止的固定有效期。

P04 只有在当前实例和目标全部匹配、未过期、一次性认领成功，且系统原始事实同时满足 `%e == %i`、`%c == 0` 时才允许把该退出归为正常并免除升级转储；最终分类还须与主管当前 attempt 的有效授权一致，不能只信任文件或 `draining`。失败、超时、换 run/实例、外部终止、错身份、过期、旧/重复/迟到通知均使 intent 失效或不可再次消费。P05 明列合法正常零退出、外部零码、旧 intent、重复/迟到和 PID 复用反例，时序、生命周期和包内证据都可观察。
