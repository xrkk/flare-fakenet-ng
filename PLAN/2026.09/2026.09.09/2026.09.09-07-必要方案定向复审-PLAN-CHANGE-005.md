## 3. AUD-PC-003 定向闭合

### AUD-PC-003｜SCM 停止失败的有限合法结束

**结果：通过；仅在本批必要方案审核中关闭。**

05号最小反例是服务先进入 `SERVICE_STOP_PENDING`，恢复审计失败后再报告 `SERVICE_RUNNING`。该转换不符合 Windows SCM 状态机，不能用偶然 API 成功或当前 VM 观察代替正式合同。当前正式需求 v3 与总纲 v5 §17已经撤销该草案，并由 PLAN-CHANGE-005 固定以下唯一顺序：

1. LocalSystem或本地Administrators经既有本地 CLI `stop`发送固定用户控制码128；该控制不接收任意参数，也不增加 MCP 工具、网络端点、主管或看门狗。
2. 第一阶段始终保持 SCM `RUNNING`且不宣告 `SERVICE_ACCEPT_STOP`。短 handler只提交唯一串行预停 worker；worker原子进入 `draining`、拒绝新变更、不排队，HTTP只读诊断继续可用。
3. 第一阶段复用同一有界停止、必要 Job终止、补偿与完整恢复审计。审计失败或超时在硬期限内写明确失败结果，领域保持 `failed/draining`及恢复责任，SCM仍为 `RUNNING`，不进入 `STOP_PENDING`、不触发 Recovery、升级器非零失败且不得替换文件。
4. 只有受管树退出、全审计通过、锁和控制权释放、领域真实 `stopped`并冻结全部变更后，服务才报告 `RUNNING+SERVICE_ACCEPT_STOP`。确认状态可查询后才原子发布当前 attempt 成功结果；CLI还要同时确认当前活动实例/attempt与 SCM接受位，才发送标准 STOP。
5. 第二阶段才合法进入 `STOP_PENDING→STOPPED`。HTTP关闭、日志刷新和服务资源释放最多30秒；checkpoint只随实际退出推进。第二阶段意外错误仍以非零 `STOPPED`/异常处理结束，不能报告干净退出。

该状态机同时保留记录024的完整清理和失败在线诊断目的、记录026的无 Recovery 循环与不自动启动 FakeNet保证，并消除了非法逆向状态转换。Microsoft状态机依据仍为：`STOP_PENDING`后唯一合法下一状态是`STOPPED`；pending checkpoint只能报告真实进展。05号反例已可被规范与ACC-019直接证伪。

**最小反例：** 实施者读取P03冻结表或P04原ACC-019正文，按旧文字让运行期 `SvcStop`直接进入清理；这会绕过控制码128，并重新制造第一阶段 `STOP_PENDING`无法失败在线的问题。总纲曾同时把“当前需求blob”写成v2对象，也会让固定来源身份不一致。

**最小闭合条件：** 当前P03/P04正文直接替换旧 `SvcStop`触发和预停全程checkpoint指令，不能只依赖尾部覆盖；总纲当前需求blob必须精确匹配需求v3，规范优先级必须包括v3。

### AUD-PC-006｜成功结果发布早于 SERVICE_ACCEPT_STOP 的竞态

**最小反例：** 预停worker先写 `service-stop-result.json=success`，再向SCM报告接受STOP。CLI看到成功文件立即发STOP，SCM仍拒绝；规范若不规定等待/重试，CLI结果和实际服务状态不可确定。

**最小闭合条件：** 冻结成功、SCM接受位可观察、当前attempt成功发布和CLI发STOP之间必须有单一顺序，并把瞬时尚未就绪、身份漂移及总硬限写入可验收结果。

**结果：已闭合。** 需求v3与总纲§17固定“冻结→报告并确认`RUNNING+SERVICE_ACCEPT_STOP`→原子发布当前attempt成功→CLI双重核对→标准STOP”；瞬时未就绪只在同一总硬限内有界等待/重试，实例身份漂移直接失败。P04/ACC-019原生覆盖成功发布竞态。

### AUD-PC-007｜在途操作超限后的迟到回写和重试重叠

**最小反例：** 已接受生命周期worker超过60秒，预停先失败；旧worker随后把状态回写为`healthy`或清除恢复责任，同时新预停worker开始清理同一资源，产生状态回退、责任丢失或双worker竞态。

**最小闭合条件：** 明确60秒排空到期的失败结果；为旧worker建立本次实例内发布栅栏；禁止迟到健康/成功/清责任，合并新增实际恢复责任；旧操作终止前禁止新收敛worker，终止后才允许重试；用真实迟到完成注入验收。

**结果：已闭合。** 需求v3与总纲§17把到期结果固定为`inflight_timeout`，SCM保持`RUNNING`、领域保持`failed/draining`。迟到worker只能完成既有动作并合并责任，不能发布健康/成功或清除责任；其终止前后续预停共享失败结果或明确拒绝，终止后才创建新尝试。该栅栏明确为进程内结果发布约束，不扩张`state.json`、事务日志或命令重放。ACC-019要求真实证明无状态回退、无重叠worker和无责任丢失。
