## 3. AUD-005同根因复开：触发熔断

- 稳定ID：AUD-005；风险：高；首次提出：05首次有效全面审核。首次处理：06 §1 AUD-005行。当前状态：同根因复开，熔断。
- 来源层级：用户已确认04 D6（五类×三画像且流量中注入）；方案REQ-SST-09；既有候选真实触发代码；用户审核收敛门禁。
- 发现来源分类：本轮变更仍未解决前轮反例；不是审核标准漂移，不是前轮覆盖遗漏，不另编新AUD稀释复开。
- 根因归类：**方案抽象错误**——将arm、实际trigger、流量相位混为满足同一要求的证据。

证据链与实际变化：

| 对象 | 可复核事实 |
| --- | --- |
| 05 AUD-005 | 明确指出listener_stop/child_hang只在start处理触发；“提前arm又可能在流量开始前消费”；要求五类真实触发路径、receipt和流量重叠，必要时先Spike |
| 06 AUD-005处理行 | 同意，称新增五窗口、arm/触发时序及长连接跨越arm点已经满足闭合条件；没有提供完成的可行性Spike证据 |

| v0.3 IMP-SST-05 | 明确串行W-config→W-start→W-traffic→W-stop→W-post；前三类start前arm、start处触发；长连接跨越arm点只写在后两类流量中arm说明中 |
| v0.3 ACC-SST-07 | 把“receipt实际触发 + arm点与长连接重叠”并列作为流量中故障证明；arm和trigger仍未统一为实际触发时刻 |
| managed.py:330—333 | inject_listener_stop / inject_diverter_stop / inject_child_hang均先于probe_instance，均处在start请求处理分支 |

| faultinject.py触发函数 | 消费armed fault并实施关闭socket/handle或创建挂起子进程；receipt表明消费事实，不能单凭它证明当时已有所需流量 |

决定性反例（只需选listener_stop一类即可否定15/15合同的可实现闭合）：

按当前串行顺序，`arm → start请求 → listener_stop实际trigger → start响应/healthy（若可得） → W-traffic首个探针`。故 `t_trigger < t_first_traffic`；若start不能发布healthy，则W-traffic甚至无法按本方案定义开始。两种路径都不能证明04 D6要求的“实际注入发生在流量进行中”。这与05已经指出的“提前arm在流量开始前消费”完全相同；给阶段命名和补receipt没有排除该反例。

对policy_pause/cleanup_error，长连接跨越arm点也只证明准备注入时有连接，未证明连接持续到stop处的实际trigger。此为同一arm/trigger混淆的补充，不另开意见。

影响：IMP-SST-05/07、ACC-SST-05/07及15故障覆盖、时间窗健康/日志和流量证据。不能继承06“已闭合”，不能把“在同一情景出现流量与故障”降格为“流量中故障”。本轮不否定已经补正的停止后健康豁免，也不复开AUD-001；只凭同根因的未解决部分触发规则。
