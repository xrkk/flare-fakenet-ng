### 2.2 目标行为

正常:
- T1 新宿主工具 `test/mcp/acceptance/scenario_suite.py` 提供子命令
  `generate / preflight / run / resume / verify / summary`, 每个子命令输出机器可读
  JSON 与人类可读摘要; 证据全部落 `Logs/fakenetng-mcp/` 下套件目录 (S6)。
- T2 `generate` 以固定种子产出 100 个情景区分明确的清单 (配置档×生命周期链×流量
  画像×交错模式), 同种子再生逐字节一致, 每个情景含 ≥10 个接口的调用计划。
- T3 `run` 串行执行情景: 每情景经 MCP 接口完成配置装载/生命周期, 同时在 VM 内产生
  真实流量 (含放行/拦截边界会话主干), 全程健康采样; 单情景时长目标 2-5 分钟,
  全套件估算 4-8 小时 (估算值 U-5, 以实测为准), 支持断点续跑。

异常:
- A1 `preflight` 任一项失败 → 打印阻断原因清单, 非零退出, 不执行任何情景 (不降级,
  见 fallback F2)。
- A2 情景失败 → 该情景记录归档 (文件名加描述后缀); 继续下一情景前必须通过
  继续前置门 (IMP-SST-05: 无未消费故障文件、无本套件残留探针进程/配置/pktmon
  会话、受管进程已恢复 stopped); 门不可验证时停止套件而非继续 (fallback F3)。
- A3 Win10VM MCP 会话中断或有界超时 (单次调用 120s) → 重连 ≤3 次/间隔 30s;
  超时/中断后按"未知结果对账"处理 (get_status/get_events 核实副作用是否已发生,
  已发生则采纳结果, 未发生且锁仍有效则以新 command_id 重试一次); 仍不可恢复 →
  该情景记 `blocked` (区别于 fail 与 skip), `resume` 经对账后可续 (fallback F1)。

边界:
- B1 覆盖计数恰达下限 (某接口仅出现 5 次) 时生成与复验均通过; 生成器构造保证不
  依赖随机凑数。
- B2 情景主干会话的取证证据 (pktmon 导出及关联链) 缺失或不可关联 → 该情景裁决
  FAIL, 不跳过不软过 (fallback F4)。
- B3 `resume` 对 `pending/blocked` 直接续跑; 对中断遗留的 `running` 先执行恢复
  对账 (服务仍持本 controller 的 run → 有界等待终态后正常完结; 服务 stopped →
  该 attempt 记 blocked 后以新 attempt 重跑; 服务持外来 controller 的 run → 停止
  整个套件并保留证据), 不重复已 pass/fail 的情景。

状态变化:
- C1 每情景状态机 `pending → running → pass | fail | blocked`, 状态持久化于套件
  目录, `verify/summary` 汇报分布。pass/fail 记录一经写入不可被 `resume` 覆盖;
  宿主中断遗留的 `running` 由恢复协议对账后转为可重试attempt (IMP-SST-05)。
- C2 服务生命周期经 MCP 可见: `stopped →(start)→ healthy →(stop)→ stopped`;
  过渡态 `recovering` 与带 run_id 的 `failed` 属预期中间状态, 停止后健康三输入
  全 False 属预期终态 (S8 行 452 区)。情景裁决按 §4 窗口模型分相位断言, 不使用
  "全程 healthy" 的单一谓词。

窗口模型 (按 VM 时间事件界定，由 IMP-SST-05 执行、IMP-SST-07 裁决):
- W-config: 服务 stopped，配置/身份校验；故障情景先启动 pktmon 并确认捕获有效，再启动 VM 目标出站发射器，最后 arm/start。启动前连接不自动计作受管流量。
- W-start: 从 start 请求到该请求返回 healthy，或健康门拒绝后进入自动停止。listener_stop/diverter_stop/child_hang 在此注入；receipt 只证明指定 fault/nonce 被消费，实际作用须另按 §4.1 证明。
- W-traffic: 仅在真实发布 healthy 后存在；健康采样仍须全部 healthy。child_hang 的正常启动分支进入此窗；listener_stop/diverter_stop 的有效启动失败分支不虚构此窗。
- W-stop: 从显式或自动 stop 请求至 stopped；policy_pause/cleanup_error 在此实际作用。它们的 arm 发生在 W-traffic，但不作为注入时间。启动失败自动停止不重复发起新 start 或假设已运行探针阶段。
- W-post: stopped 后恢复验证及停止捕获、导出证据；故障终态仍要求 last_run_outcome=failed、五节恢复审计、锁释放、受管树清空、连续探活及 incident。其后另作正常启动→healthy→停止的恢复轮。

故障情景窗口语义 (S16 DEC-SST-START-01，仅作用于15个故障情景):
- 允许 starting 期注入，不要求先 healthy；“允许指定注入导致的启动失败”不等于“三类均必须启动失败”。逐类状态与归因见 §4.1 表。
- 重叠义务: 同一 run 的一条目标出站策略会话必须覆盖实际作用时刻。只有作用区间 [trigger_lo, trigger_hi] 时，要求该会话确定存活区间完整覆盖此区间；仅相交不能通过。receipt mtime 不代入触发时刻。宿主入站 hammer 仅辅助。
- “进行中”须由已建立且未结束的目标会话、同run策略处理及连接/包序列证明；不要求触发瞬间恰有包，不拼接重试连接或不同run的首末包。
- 异常只按 §4.2 固定集合与完整块匹配放行；同名线程标题不是白名单。没有足够证据时失败，不由实施者自动扩大集合或安排后序审核代替当前判据。

## 4. 数据与接口契约

- `scenario-manifest.json`: 数组, 元素 `{scenario_id, seed, config_profile,
  lifecycle_chain, traffic_profile, interleave_pattern, fault_class,
  interface_call_plan[]}`; `interface_call_plan` 满足 **distinct(tool) ≥10** (同一
  接口重复调用不计入下限), 元素为 S7 接口名 + 参数摘要 + 期望结果类别 (成功 /
  契约性拒绝, 拒绝须含期望错误身份与无副作用后置断言)。
- `matrix-manifest.json` (缩量输入合同, IMP-SST-02): 首个缩量轮写入证据根目录,
  字段 `{mode: 'reduced', candidate_id, source_commit, package_sha256,
  evidence_root, planned: {normal-builtin: N, normal-custom: M, fault-<类>: K},
  created_at}`; final/summary 读到它则以 planned 计数替代内置 50/50/10 全量合同,
  读不到则维持全量合同 (默认不变); 记录与 planned 不一致、旧全量轮混入、或
  身份字段与 candidate 不符 → integrity 失败 (退出码 3)。
- `scenario-{id}.state.json` (状态日志): `{phase, controller_id, attempt,
  run_chain[], started_at, updated_at}`; `run_chain` 每实际 run 一项
  `{run_id, started_at, stopped_at, pcap_file, pcap_sha256, log_slice_offsets}`;
  restart 类交错产生多 run 链。pass/fail 判决记录写入后不可变。
- `scenario-{id}.json` (每情景判决): `{state, verdict{interface_semantics,
  healthy, log_clean, evidence_integrity}, interface_calls[{tool, command_id,
  args_digest, result_digest, ok, duration}], traffic_evidence{probe_results,
  capture_views[]}, health_trace{window, sample_count, all_healthy}, run_chain,
  recovery{five_section_audit, lock_released, tree_empty, outcome}, seed,
  archive_suffix?}`。
- `coverage-report.json`: 15 接口 × 情景矩阵, 以**实际执行**的 interface_calls
  按接口对 distinct scenario_id 计数, 并与 manifest 计划逐情景核对。
- `summary.json`: 裁决分布 (pass/fail/blocked)、轴分布、覆盖复验结论。
- MCP 接口使用契约: 乐观锁参数按 S7 (`command_id` = `{scenario_id}-{attempt}
  -{seq}` 确定性构造; `expected_state_version`/`expected_sha256` 基于上次成功
  读); 交错计划允许"故意过期的锁参数"调用, 期望契约性拒绝 (错误身份匹配 + 事后
  state_version 未变); 每次调用的 controller/run 身份从响应登记 (S7
  controller_identity)。
- 取证契约 (IMP-SST-06): 每情景每 run 一个 pktmon 会话 (S11 形态, 与 DumpPackets
  无关的独立捕获层), 故障情景在 W-config 的发射器启动前确认捕获有效（良性情景在首探针前），W-post 后停止导出; DumpPackets=Yes 的
  配置档 (default/process_redirect, S10 实测) 额外自然产生 dual-PCAP 视图; 不为
  取证改写产品配置。正/负探针逐条记录 `{name, nonce, command, exit_code,
  output_digest, verdict, correlation}`; 关联规则: 探针结果 ↔ 策略/服务日志流
  元组 (src ip:port) ↔ pktmon 流, 按元组关联; 正向 curl 一律 `--noproxy *` 且
  nonce 置于 URL 路径。
- `scenario_suite.py` CLI 契约: 子命令 `generate|preflight|run|resume|verify|
  summary`; 公共参数 `--target-base-url` (必填, 无默认)、`--win10vm-mcp` (必填,
  无默认)、`--suite-root` (默认 `Logs/fakenetng-mcp/scenario-suite-20260912`);
  各子命令必填输入、输出 schema 与退出码见对应 ACC; stdout 首行单行 JSON
  `{output_dir}`。
- `scenario_suite.py` 退出码契约: 0=本子命令全部通过; 2=用法/参数错误或 preflight
  阻断 (F2); 3=run/verify 完成但存在 fail 情景; 4=run 因 blocked/恢复对账失败/
  继续前置门不可验证而未完结 (需 resume 或人工介入)。

### 4.1 故障作用、会话区间及证据裁决 Spike 契约

来源: REQ-SST-09、S16 边界①②④⑤⑥；11 审计 AUD-005/011 为修改依据，不替代规范来源。本节是固定候选、零产品改动边界下的**证据前置门**；没有证据产物时不得宣称套件故障路径已具备实施验收资格。

证据数据落在 `Logs/fakenetng-mcp/scenario-suite-20260912/spike-evidence-contract/`。新增宿主离线工具（归 IMP-SST-07）`test/mcp/acceptance/sst_fault_evidence.py`，仓库根执行：
`python3 test/mcp/acceptance/sst_fault_evidence.py --input <case.json> --evidence-root <原始证据目录> --output <result.json>`。
退出码0=全部谓词成立；3=断言失败/缺证/未知归因；2=参数或schema错误。stdout及result均为 `{schema:"sst.fault-evidence.result.v1", case_id, passed, checks:[{id,passed,reason,evidence_refs}], unsupported_observations:[]}`。离线检查不操作VM、不授予采样或套件执行权限。

输入 `sst.fault-evidence.case.v1` 必含 `{case_id,candidate_id,run_id,fault,nonce,clock,receipt_ref,trigger,session,start_response_ref,health_refs,stop_refs,recovery_refs,exception_refs,files}`。`files` 含相对路径/bytes/sha256；引用为 `{path,byte_start,byte_end,event_key}`，解析器必须从原始文件提取字段并对照输入，不能信任作者手填的布尔结论。路径不得越出证据根。

- `clock={domain:"vm-utc",resolution_ns,discontinuities:[]}`；每个时间记录为 `[earliest_ns,latest_ns]`。日志毫秒值按覆盖该毫秒的区间处理；更精确输入也不得声称超过原始精度。发现时钟跳变、混入未校准宿主时钟或缺少精度，失败。原始本地时区时间显式换算UTC；PID均配creation身份，防复用。
- `trigger={kind,lower_ref,upper_ref,success_refs}`：保守下界优先来自VM原位置receipt创建时间的原始元数据导出（文件内容/路径/run/nonce/哈希及时间精度一并保留，因clear写入先于动作，只可作动作之前的界）；没有该元数据时采用同run子进程接收对应start/stop请求的IPC事件作为更宽下界。上界只能来自下表证明实际动作已发生的原始观测。使用下界事件的earliest与上界事件的latest构造区间。receipt不能作为成功观测、上界或精确触发时间；复制到宿主后的mtime、手填timeline均不构成原位置时间证据。采用过宽下界使启动前区间无法被受管会话覆盖时应失败，不收窄成猜测值。动作成功不能证明、只有probe=False或区间过宽不能被一条会话覆盖，均失败，不猜测中点。
- `session={connection_id,probe_pid,probe_creation,nonce,src,dst,protocol,established_ref,managed_ref,end_ref,packet_refs}`。连接ID区分每次重试和同五元组复用。开始界取连接建立证据与同run首次策略处理证据两者较晚的latest；结束界取该连接首个FIN/RST、探针close/EOF/error观测中最早的earliest。捕获未覆盖完整区间、缺结束证据或不能排除重建连接则失败。判断 `session_begin_upper <= trigger_lo <= trigger_hi <= session_end_lower`，无需触发瞬间有包。
- 受管关联必须含该run日志的探针PID/源元组→策略处理或中继映射→pktmon连接证据；中继改写须保留两侧元组映射，不能仅靠时间邻近。VM出站目标与桶配置一致；发射器在start前建立而从未被本run策略处理的连接不计。TLS nonce使用应用请求路径，不向443直接发送明文nonce；重试生成新connection_id，不能把循环总运行区间当连接区间。

| 故障 | 实际作用与可接受成功观测 | start/后续轨迹与归因边界 |
|---|---|---|
| listener_stop | 关闭绑定listener socket；同run匹配§4.2的WinError10038异常块，并有IPC listener描述符失效/线程死亡的具体条目；上界取两项观测较晚者 | 允许该listener失效引起probe=False而启动门拒绝；其余初始化、capture_error、超时或错误异常不得借receipt归因。若start短暂返回healthy，必须按正常S8发现已证故障并收敛，不能把故障后的不健康样本当W-traffic healthy通过；此分支缺充分归因证据则失败 |

### 4.2 固定异常集合及完整块匹配

来源: S16边界③、faultinject.on_stop_error源码及既有Spike run.log第62—69行。允许集合：listener_stop仅L1；cleanup_error仅C1；diverter_stop/child_hang/policy_pause均为空集合。空集合意味着任何扫描命中都失败，不意味着预测这些故障必然无日志异常；真实证据若不兼容，保留失败，不自动扩充白名单。

- L1：logger=`managed.thread`；标题严格为 `Unhandled exception in managed thread Thread-<十进制编号> (serve_forever)`；完整Traceback帧（忽略目录前缀、保留文件basename/函数次序）为 `threading.py:_bootstrap_inner → threading.py:run → socketserver.py:serve_forever → selectors.py:select → selectors.py:_select`；末行为 `OSError: [WinError 10038] <系统本地化消息>`。仅允许归一化线程编号、源码行号、路径前缀和10038后的本地化说明，不能归一化错误码、异常类型或函数序列。没有标题的孤立Traceback不匹配L1。
- C1：logger=`managed`，完整Traceback末行为 `RuntimeError: injected cleanup error`；末帧必须为 `faultinject.py:on_stop_error`，其直接调用帧来自 `managed.py` 的stop分支。不得只凭消息子串放行；不允许额外cause/context异常链。源码行号/目录前缀可归一化，函数及错误消息不可。
- 按带时间戳日志头分块，Traceback与其续行归入同一块；畸形/截断块、异常链、块外扫描字符串均失败。每块须在同run证据清单中，fault/nonce消费身份匹配，并满足§4.1对应故障作用及状态归因。记录原始字节范围与归一化结果，保证同一块中的标题和Traceback不会一个放行另一个漏扫。
- L1限定W-start或其故障健康检查收敛区间且须有对应listener失效证据；C1限定W-stop且须匹配同次stop IPC error。W-config、良性全部窗口、故障正常W-traffic中的异常无此例外。若多个错误使归因不唯一，失败；已放行块不掩盖同窗口其他错误。
- 不通过修改产品健康函数实现白名单；产品S8继续原样发现异常并失败。这里只裁决“该负向情景是否按指定故障和恢复合同结束”。
