## 3. 总体架构与不变量

### 3.1 单进程逻辑架构

`fakenetng-mcp` 是一个由 Windows SCM管理的无界面服务进程。以下名称表示同一进程内的逻辑职责，不要求建立额外进程或通用框架：

1. **HTTP/MCP 边界：** 只在配置的 VM host-only IP和固定端口提供 MCP `2026-07-28` Streamable HTTP单 endpoint，接收探活、只读诊断和领域变更请求。
2. **运行协调器：** 维护状态、状态版本、当前命令、单控制者和严格串行的变更执行；只读查询不改变状态。
3. **配置边界：** 保护内置配置，只在 MCP专用自定义根内管理原始 `.ini`，负责路径收敛、校验、版本冲突和活动锁。
4. **FakeNet-NG 主管：** 通过现有 FakeNet入口管理一个实例，把完整受管进程树放入 kill-on-close Job Object，维护真实健康。
5. **网络保护与恢复：** 在打开主 WinDivert句柄前，把 MCP响应流按“允许的宿主 IP + VM MCP源/监听端口”排除；启动前保存基线，停止后恢复并审计。
6. **证据与产物登记：** 直接写普通日志、基线、incident和产物元数据；证据不驱动命令重放。

### 3.2 强制不变量

- 每台目标 Windows VM同时最多一个 `fakenetng-mcp`，每个 MCP同时最多一个受管 FakeNet-NG。
- MCP模式无 GUI；GUI人工模式与 MCP模式互斥。
- 多个 AI可连接并完成无副作用的探活和完整只读诊断；每次 FakeNet-NG运行只有一个稳定 `controller_id` 可以变更状态。
- 控制者没有租约、心跳或失联超时；Agent、会话和连接重启不释放控制权。
- FakeNet-NG不能捕获或破坏 MCP控制响应。保护参数或主 filter语义无法校验时，禁止启动 FakeNet-NG。
- `healthy` 必须由进程、关键初始化和主动探测共同证明；日志出现未处理 Python异常或核心明确失效时必须撤销健康。
- 只有进程、网络、服务、端口和配置锁恢复审计全部通过，才能报告 `stopped`并释放控制权；恢复失败保持 `failed`且禁止新启动。
- MCP崩溃时由 Job Object终止受管进程树，由 SCM重启 MCP；重启后的 MCP只恢复和审计环境，不自动重启 FakeNet-NG、不续接或重放旧命令。
- 产品不开放任意命令、任意路径文件读写、产品内文件正文下载、数据库、通用事务/事件框架或独立看门狗。

## 5. 生命周期、数据流与结束条件

### 5.1 服务启动与恢复

1. SCM启动 `fakenetng-mcp`；服务取得 OS级单实例排他权、加载机器级配置并建立/核验监听和防火墙规则。
2. 无恢复责任时进入 `stopped`，等待 AI明确启动；不得自动启动 FakeNet-NG。
3. `state.json` 表示上次仍需恢复时进入 `recovering`：不得重放旧命令或启动 FakeNet-NG，只依据基线路径恢复并审计。
4. 恢复审计通过后写入真实 `stopped`；快照损坏/缺失且存在残留，或恢复审计失败时进入 `failed`并禁止启动。

### 5.2 显式启动

1. 请求必须携带格式有效的稳定控制者 Header、`expected_state_version`和`command_id`；服务必须处于允许启动的真实状态，且没有其他变更执行。
2. 校验选定配置、解析后路径和 SHA-256；核验监听、防火墙、允许宿主 IP、VM监听端口和主 WinDivert filter排除语义。
3. 捕获启动前进程、WinDivert、路由、DNS、相关服务、监听端口和配置锁基线。
4. 原子写入带需要恢复标记的当前 `state.json`；写入失败则拒绝启动。
5. 取得活动配置锁，创建 kill-on-close Job Object并启动唯一 FakeNet-NG进程树，进入 `starting`。
6. 只有进程存活、关键初始化证据满足和主动健康探测通过才进入 `healthy`；部分功能风险进入 `degraded`；终止性证据进入 `failed`并触发保护性收敛。

### 5.3 运行期控制与观察

- 所有连接都能探活并读取完整健康、失败原因、异常详情、运行/配置身份和产物元数据；无 Header或其他控制者不得变更状态。
- 当前控制者可执行约定的启动后变更；生命周期变更严格串行，不后台排队。版本、身份、状态或当前操作冲突立即结构化拒绝。
- 当前进程能识别的相同 `command_id` 重试返回原操作/结果，不重复执行；MCP进程重启后不恢复该命令的执行语义。
- `restart` 必须绑定原 `run_id`，完成同一套停止、恢复审计和新启动前置校验；不能绕过清理。
- 运行中持续检查主动健康和本次运行日志。未处理 Python异常或高置信度核心失效必须立即撤销健康并公开原因。

### 5.4 停止、故障收敛与结束

1. 正常停止或明确失效先执行有硬上限的优雅停止；明确失效还必须先有界采集 incident证据。
2. 超过上限或清理异常时，保存阶段、耗时和可得现场，只强制终止本次 Job Object中的受管进程树。
3. 根据启动前基线恢复并审计 WinDivert、相关进程、路由、DNS、被改动服务、监听端口和配置锁。
4. 全部通过后清除需要恢复标记、释放控制者和活动锁，状态为 `stopped`；若本次由内部失效触发，保留 `last_run_outcome=failed`及证据引用，不得把运行结果伪装成成功。
5. 任一恢复项失败时保持 `failed`，禁止新启动。测试流程先导出证据到 `Logs/`，定位和修复根因，恢复指定干净快照，部署新候选并从头重跑受影响完整计数。

### 5.5 可处理的正常服务停止与升级

1. SCM正常停止信号或升级流程请求停止服务时，MCP先进入受控退出阶段：拒绝所有新的状态变更，不接受后台排队，同时在服务仍可响应期间保持探活、状态、错误和证据查询可用。
2. FakeNet-NG正在运行时必须调用§5.4同一套有界优雅停止、必要强制收敛、补偿恢复和环境审计；已有恢复责任时必须先完成恢复审计。正常服务控制信号不得直接降级为关闭MCP句柄并依赖Job kill-on-close的崩溃路径。
3. 只有环境审计全部通过、活动配置锁和控制权已释放且状态为真实`stopped`后，MCP才可刷新当前状态和日志、关闭endpoint、释放单实例排他权并向SCM完成正常退出。升级安装必须等待该条件后才能替换服务文件。
4. 环境审计失败时保持`failed`、禁止新启动并继续提供可得诊断，不得向SCM或升级器宣称干净停止；随后按FB-007导出证据、修复和快照重测。若进程被外部强制终止，则转入OUT-007已定义的Job Object/SCM异常收敛路径，但不能把它计为正常停止成功。

## 6. 接口与最小数据合同

### 6.1 MCP 能力合同

总纲冻结能力而不虚构尚不存在的工具名。P02必须为以下能力建立明确 schema：

- 无副作用：探活、完整状态/健康/失败详情、近期事件、配置枚举与校验、受管产物枚举和元数据读取。
- 配置变更：在专用自定义根内创建、导入、读取、编辑、重命名、删除和加载原始 `.ini`；内置配置永远只读。
- 生命周期变更：启动、停止、重启；只允许当前控制者执行启动后的状态变更。
- 失败态：状态/错误/证据查询保持可用；不得提供任意命令、任意系统恢复或污染环境下的强制启动入口。

所有变更请求至少具有 `command_id`、`expected_state_version`及自动发送的控制者 Header。配置变更还必须携带所见版本或`expected_sha256`。响应必须公开当前状态、状态版本、相关 `run_id`/命令身份、是否产生状态变化及结构化失败类别；具体 JSON字段拼写由 P02冻结并形成机器可检验 schema。

### 6.2 配置数据合同

- 路径必须先在专用自定义根内规范化，再拒绝绝对路径、`..`、符号链接、硬链接和 Windows重解析点逃逸。
- 创建/导入默认不可覆盖；编辑使用临时文件、内容和语义校验、落盘校验及同目录原子替换。
- 内置配置不允许修改、重命名或删除。
- 活动配置从启动到清理完成保持锁定，并记录解析路径和 SHA-256；停止态同一配置冲突立即拒绝，不同配置可以并行。
- 每次自定义配置创建、导入、编辑、重命名或删除都必须在CON-006允许的普通日志中审计：记录控制者身份、时间、`command_id`、目标配置、操作、前后版本与SHA-256及结果。失败、冲突和无状态变化的尝试也必须记录实际结果；这些日志只用于归因，不得成为事务日志、事件重放或状态恢复来源。

### 6.3 当前快照与证据合同

- `state.json` 是覆盖写的当前恢复便签，不是历史库。关键生命周期变化使用同目录临时文件、刷新和原子替换。
- 普通日志和 incident只用于诊断，不驱动状态、命令或事件重放。
- 受管产物元数据至少包括规范化 VM路径、类型、大小、完成状态和完成后的 SHA-256；产品 MCP不返回正文，也不提供下载路由。
- incident位于 `%ProgramData%\FakeNet-NG-MCP\artifacts\<run_id>\incident\`，清单逐项记录结果、失败原因、大小和 SHA-256；基础证据及条件式转储内容必须完整承接 REQ-012。

## 7. 稳定交付结果 OUT

### OUT-001｜唯一无头主管

交付一个 SCM托管、无 GUI、OS级单实例的 `fakenetng-mcp`，只管理一个 FakeNet-NG；服务启动后为 `stopped`，由 AI明确启动。第二 MCP、第二受管实例和 GUI共控均被明确拒绝。适用前提和重新裁决条件沿用 REQ-001、CON-001、NON-001、NON-009。负责：P03；验收：ACC-001。

### OUT-002｜协议与客户端可用入口

交付 MCP `2026-07-28` Streamable HTTP单 endpoint及目标 AI真实发现/工具调用、Python实现和最小 Windows包启动证据。客户端不兼容时停止 P01并公开重新裁决兼容层，不静默切换旧 transport。负责：P01；验收：ACC-002。

### OUT-003｜受限 host-only 暴露面

服务只绑定配置的 VM host-only IP和端口，安装幂等维护只允许配置宿主 IP的防火墙入站规则；当前受信单宿主实验网按决定使用明文且无 TLS/token/OAuth/Origin，并明确记录剩余风险和重新裁决条件。负责：P01；验收：ACC-003。

### OUT-004｜FakeNet 故障域外的控制链路

启动 FakeNet-NG前在唯一主 WinDivert filter中排除 MCP响应；正常接管、初始化失败、未处理异常、核心线程异常、卡死和退出均不能由 FakeNet-NG切断链路。参数或排除条件不能验证时失败关闭。保证不扩张到 MCP自身、Windows、网卡、VM或宿主基础设施故障。负责：P03；验收：ACC-004。

### OUT-005｜封闭工具与完整只读诊断

交付需求列明的领域能力；所有可达连接均可做无副作用的完整只读诊断，只有授权控制者可变更。任意命令、任意路径读写、未授权变更和产品正文下载不可达。负责：P02；验收：ACC-005。

### OUT-006｜真实健康和假活处置

交付必备状态、启动门槛、持续主动探测和日志未处理异常识别；不能以进程存在代表健康。明确失效必须撤销健康、报告可复核原因并进入保护性处置；复现既有缺陷时按证据修复，未阻塞工作可继续。负责：P03；验收：ACC-006。

### OUT-007｜Job Object 与 SCM 崩溃收敛

FakeNet-NG完整且仅限受管进程树处于 kill-on-close Job Object中。MCP异常退出由Job收敛、SCM重启MCP，新进程依据当前快照恢复/审计后回到真实`stopped`或`failed`，不续跑FakeNet-NG、不重放命令。MCP可处理的正常SCM停止或升级不得使用该崩溃捷径：必须拒绝新变更、保持可得查询并按§5.5调用完整停止/恢复审计，只有真实`stopped`后才退出；审计失败保持`failed`。异常路径负责P03、验收ACC-007；正常服务停止/升级的完整收敛由P04验收ACC-019。

### OUT-008｜最小当前恢复快照

只交付单个原子覆盖的当前 `state.json`及损坏/缺失/写失败处理；启动前无法写入则不启动，有残留而快照不可信则`failed`。不得引入数据库、事务日志、事件重放、迁移或诊断派生框架。负责：P03；验收：ACC-008。

### OUT-009｜受管配置边界

交付内置只读、专用自定义根完整管理、路径逃逸阻断、加载前校验、版本/哈希冲突控制、普通日志级配置变更审计及活动配置真实 Windows锁。审计记录控制者、时间、命令、目标、操作、前后版本/哈希和结果，但不驱动恢复或重放。P02负责文件/API及审计语义，P03唯一负责真实 FakeNet读取兼容和活动锁集成。最终验收负责：P03；验收：ACC-009。

### OUT-010｜稳定单控制者

多连接可观察；成功启动者的稳定 UUID通过`X-FakeNet-Controller-ID`跨 Agent/会话/连接重启继续控制，其他或无效 Header只读。无超时、租约或自动接管，ID不是安全认证。负责：P02；验收：ACC-010。

### OUT-011｜串行、版本与幂等

变更严格串行、不后台排队；身份、版本、状态或活动操作冲突立即结构化拒绝；同一当前进程可识别的`command_id`不重复执行；停止态配置用乐观冲突控制；崩溃后不续接命令。负责：P02；验收：ACC-011。

### OUT-012｜100 次正常恢复门禁

同一最终候选在指定真实 Win10 VM对代表性内置与自定义配置完成至少100次连续正常启停，每轮链路、进程/WinDivert、路由、DNS、服务、端口和配置锁均回到基线，零未解释残留、零断联、零虚假`stopped`。机制由P04提供，发布验收负责：P05；验收：ACC-012。

### OUT-013｜每类 10 次故障收敛门禁

同一候选对策略暂停、代表性 listener停止、diverter停止、受管子进程不退出和清理异常等每类至少重复10次，逐轮满足OUT-012；失败修复后从干净快照重跑受影响完整计数。机制由P04提供，发布验收负责：P05；验收：ACC-013。

### OUT-014｜根因级 incident

每个终止性故障生成结构化清单和足够开发者定位触发组件/失败链路的基础证据；挂起、原生异常、线程栈不可得或基础证据不能解释时生成 Windows用户态转储。采集有界，缺项显式失败但不能无限阻塞清理。负责：P04；验收：ACC-014。

### OUT-015｜产物元数据和带外验收导出

产品 MCP只返回受管路径及核验元数据，不返回正文或下载路由。验收时可用 Win10VM MCP或仅绑定`192.168.204.1`的临时 host-only传输服务导出到`Logs/`，核对 SHA-256并停止临时服务；这些不是产品依赖。负责：P04；验收：ACC-015。

### OUT-017｜原生 Windows 最终候选

交付可配置、可迁移、不硬编码当前 VM身份的 Windows候选；同一源快照、包 SHA-256和manifest绑定 P01—P05证据，并在指定真实 Win10 VM完成原生安装、SCM、WinDivert、Job、锁、恢复和端到端 MCP。Linux保留TODO，宿主构建方式不能替代实机。最终负责：P05；验收：ACC-017。

## 9. ACC 验收合同

### 9.1 尚未建立的验收工具合同

当前仓库没有 `fakenetng-mcp`验收工具，因此本总纲不虚构命令。各Pxx创建工具后必须在子方案和实施记录补上真实调用，并遵守以下冻结合同：

- 工作目录：仓库根 `/home/adminn/projects/flare-fakenet-ng`。
- 输入：不可变源commit、候选包路径及SHA-256、候选manifest、需求blob、审核通过后的总纲blob、目标VM身份、配置身份和待执行ACC列表。
- 输出：`Logs/fakenetng-mcp/<candidate-id>/<acc-id>/`；至少包含`result.json`、原始stdout/stderr、逐项证据和SHA-256清单。
- 路径元变量定义：`<candidate-id>` 是P01为“不可变源commit + 候选包SHA-256 + manifest”生成并在候选期内保持不变的标识；`<acc-id>` 是本总纲已定义的实际ACC编号。二者均为输出schema元变量。
- `result.json`最小字段：`acc_id`、`p_id`、`candidate_id`、`source_commit`、`package_sha256`、`requirements_blob`、`master_plan_blob`、`environment_identity`、`started_at`、`ended_at`、`status`、`actions`、`expected`、`observed`、`evidence[]`、`blocker`。
- 退出码合同：`0=通过`、`1=验收失败`、`2=前置条件阻断`、`3及以上=验收工具自身错误`。被阻断不能计为通过或失败测试样本。
- 证据只能覆盖负责Pxx及直接依赖；除需求、总纲或生效`AGENTS.md`明确要求外，不把仓库全量健康作为单项ACC通过条件。
