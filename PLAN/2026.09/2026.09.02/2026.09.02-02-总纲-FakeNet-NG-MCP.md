## 3. 总体架构与不变量

### 3.1 单主管与独立受管进程架构

`fakenetng-mcp` 是一个由 Windows SCM管理的无界面服务进程。以下名称表示主管内的逻辑职责；实际FakeNet运行置于独立受管子进程。主管持有Job且自身不加入Job，不增加第二长驻主管或通用框架：

1. **HTTP/MCP 边界：** 只在配置的 VM host-only IP和固定端口提供 MCP `2026-07-28` Streamable HTTP单 endpoint，接收探活、只读诊断和领域变更请求。
2. **运行协调器：** 维护状态、状态版本、当前命令、单控制者和严格串行的变更执行；只读查询不改变状态。
3. **配置边界：** 保护内置配置，只在 MCP专用自定义根内管理原始 `.ini`，负责路径收敛、校验、版本冲突和活动锁。
4. **FakeNet-NG 主管：** 通过现有 FakeNet入口管理一个实例，把完整受管进程树放入 kill-on-close Job Object，维护真实健康。
5. **网络保护与恢复：** 在打开主 WinDivert句柄前，把 MCP响应流按“允许的宿主 IP + VM MCP源/监听端口”排除；启动前保存基线，停止后恢复并审计。
6. **证据与产物登记：** 直接写普通日志、基线、incident和产物元数据；证据不驱动命令重放。

### 3.2 强制不变量

- 每台目标 Windows VM同时最多一个 `fakenetng-mcp`，每个 MCP同时最多一个受管 FakeNet-NG。
- MCP模式无 GUI；GUI人工模式与 MCP模式互斥。
- 多个 AI可连接并完成无副作用的探活和完整只读诊断；每次 FakeNet-NG运行只有一个稳定 `controller_id` 可以变更状态。
- 控制者没有租约、心跳或失联超时；Agent、会话和连接重启不释放控制权。
- FakeNet-NG不能捕获或破坏 MCP控制响应。保护参数或主 filter语义无法校验时，禁止启动 FakeNet-NG。
- `healthy` 必须由进程、关键初始化和主动探测共同证明；日志出现未处理 Python异常或核心明确失效时必须撤销健康。
- 只有进程、网络、服务、端口和配置锁恢复审计全部通过，才能报告 `stopped`并释放控制权；恢复失败保持 `failed`且禁止新启动。
- MCP崩溃时由 Job Object终止受管进程树，由 SCM重启 MCP；重启后的 MCP只恢复和审计环境，不自动重启 FakeNet-NG、不续接或重放旧命令。
- 产品不开放任意命令、任意路径文件读写、产品内文件正文下载、数据库、通用事务/事件框架或独立看门狗。

## 5. 生命周期、数据流与结束条件

### 5.1 服务启动与恢复

1. SCM启动 `fakenetng-mcp`；服务取得 OS级单实例排他权、加载机器级配置并建立/核验监听和防火墙规则。
2. 无恢复责任时进入 `stopped`，等待 AI明确启动；不得自动启动 FakeNet-NG。
3. `state.json` 表示上次仍需恢复时进入 `recovering`：不得重放旧命令或启动 FakeNet-NG，只依据基线路径恢复并审计。
4. 恢复审计通过后写入真实 `stopped`；快照损坏/缺失且存在残留，或恢复审计失败时进入 `failed`并禁止启动。

### 5.2 显式启动

1. 请求必须携带格式有效的稳定控制者 Header、`expected_state_version`和`command_id`；服务必须处于允许启动的真实状态，且没有其他变更执行。
2. 校验选定配置、解析后路径和 SHA-256；核验监听、防火墙、允许宿主 IP、VM监听端口和主 WinDivert filter排除语义。
3. 捕获启动前进程、WinDivert、路由、DNS、相关服务、监听端口和配置锁基线。
4. 原子写入带需要恢复标记的当前 `state.json`；写入失败则拒绝启动。
5. 取得活动配置锁，创建 kill-on-close Job Object并启动唯一 FakeNet-NG进程树，进入 `starting`。
6. 只有进程存活、关键初始化证据满足和主动健康探测通过才进入 `healthy`；部分功能风险进入 `degraded`；终止性证据进入 `failed`并触发保护性收敛。

### 5.3 运行期控制与观察

- 所有连接都能探活并读取完整健康、失败原因、异常详情、运行/配置身份和产物元数据；无 Header或其他控制者不得变更状态。
- 当前控制者可执行约定的启动后变更；生命周期变更严格串行，不后台排队。版本、身份、状态或当前操作冲突立即结构化拒绝。
- 当前进程能识别的相同 `command_id` 重试返回原操作/结果，不重复执行；MCP进程重启后不恢复该命令的执行语义。
- `restart` 必须绑定原 `run_id`，完成同一套停止、恢复审计和新启动前置校验；不能绕过清理。
- 运行中持续检查主动健康和本次运行日志。未处理 Python异常或高置信度核心失效必须立即撤销健康并公开原因。

### 5.4 停止、故障收敛与结束

1. 正常停止或明确失效先执行有硬上限的优雅停止；明确失效还必须先有界采集 incident证据。
2. 超过上限或清理异常时，保存阶段、耗时和可得现场，只强制终止本次 Job Object中的受管进程树。
3. 根据启动前基线恢复并审计 WinDivert、相关进程、路由、DNS、被改动服务、监听端口和配置锁。
4. 全部通过后清除需要恢复标记、释放控制者和活动锁，状态为 `stopped`；若本次由内部失效触发，保留 `last_run_outcome=failed`及证据引用，不得把运行结果伪装成成功。
5. 任一恢复项失败时保持 `failed`，禁止新启动。测试流程先导出证据到 `Logs/`，定位和修复根因，恢复指定干净快照，部署新候选并从头重跑受影响完整计数。

### 5.5 可处理的正常服务停止与升级

1. 按PLAN-CHANGE-005，管理员CLI stop或升级流程先发送固定预停控制码128（此阶段SCM仍RUNNING，标准STOP尚不接受）；MCP先进入受控退出阶段：拒绝所有新的状态变更，不接受后台排队，同时在服务仍可响应期间保持探活、状态、错误和证据查询可用。
2. FakeNet-NG正在运行时必须调用§5.4同一套有界优雅停止、必要强制收敛、补偿恢复和环境审计；已有恢复责任时必须先完成恢复审计。正常服务控制信号不得直接降级为关闭MCP句柄并依赖Job kill-on-close的崩溃路径。
3. 只有环境审计全部通过、活动配置锁和控制权已释放且状态为真实`stopped`后，MCP才可刷新当前状态和日志、关闭endpoint、释放单实例排他权并向SCM完成正常退出。升级安装必须等待该条件后才能替换服务文件。
4. 环境审计失败时保持`failed`、禁止新启动并继续提供可得诊断，不得向SCM或升级器宣称干净停止；随后按FB-007导出证据、修复和快照重测。若进程被外部强制终止，则转入OUT-007已定义的Job Object/SCM异常收敛路径，但不能把它计为正常停止成功。

## 6. 接口与最小数据合同

### 6.1 MCP 能力合同

总纲冻结能力而不虚构尚不存在的工具名。P02必须为以下能力建立明确 schema：

- 无副作用：探活、完整状态/健康/失败详情、近期事件、配置枚举与校验、受管产物枚举和元数据读取。
- 配置变更：在专用自定义根内创建、导入、读取、编辑、重命名、删除和加载原始 `.ini`；内置配置永远只读。
- 生命周期变更：启动、停止、重启；只允许当前控制者执行启动后的状态变更。
- 失败态：状态/错误/证据查询保持可用；不得提供任意命令、任意系统恢复或污染环境下的强制启动入口。

所有变更请求至少具有 `command_id`、`expected_state_version`及自动发送的控制者 Header。配置变更还必须携带所见版本或`expected_sha256`。响应必须公开当前状态、状态版本、相关 `run_id`/命令身份、是否产生状态变化及结构化失败类别；具体 JSON字段拼写由 P02冻结并形成机器可检验 schema。

### 6.2 配置数据合同

- 路径必须先在专用自定义根内规范化，再拒绝绝对路径、`..`、符号链接、硬链接和 Windows重解析点逃逸。
- 创建/导入默认不可覆盖；编辑使用临时文件、内容和语义校验、落盘校验及同目录原子替换。
- 内置配置不允许修改、重命名或删除。
- 活动配置从启动到清理完成保持锁定，并记录解析路径和 SHA-256；停止态同一配置冲突立即拒绝，不同配置可以并行。
- 每次自定义配置创建、导入、编辑、重命名或删除都必须在CON-006允许的普通日志中审计：记录控制者身份、时间、`command_id`、目标配置、操作、前后版本与SHA-256及结果。失败、冲突和无状态变化的尝试也必须记录实际结果；这些日志只用于归因，不得成为事务日志、事件重放或状态恢复来源。

### 6.3 当前快照与证据合同

- `state.json` 是覆盖写的当前恢复便签，不是历史库。关键生命周期变化使用同目录临时文件、刷新和原子替换。
- 普通日志和 incident只用于诊断，不驱动状态、命令或事件重放。
- 受管产物元数据至少包括规范化 VM路径、类型、大小、完成状态和完成后的 SHA-256；产品 MCP不返回正文，也不提供下载路由。
- incident位于 `%ProgramData%\FakeNet-NG-MCP\artifacts\<run_id>\incident\`，清单逐项记录结果、失败原因、大小和 SHA-256；基础证据及条件式转储内容必须完整承接 REQ-012。

### 19.1 同一采集责任与SPE交接的实现约束（007必要审核前细化）

全局单飞1计一个逻辑采集责任，不能误解为SPE持槽时owner的必要ACK还须竞争第二次同一锁。SPE已进入且持槽时，owner交接、结果核验、哈希、发布准备是该run/attempt的固定从属工作，沿用同一截止和全局活动额度，禁止另开槽/新采集或队列。ACK必须在主管已经固定助手真实句柄和本次责任之后发；normal-ack仍只由主管当前有效intent裁决，不交给助手自批。禁止采集助手等待会再次竞争其已持单飞锁的任务，真正数据采集I/O只在从属受管工作执行，主管状态/HTTP仅做有界状态跳转。协议握手的限定并行见下条，不可借握手之名采集数据。

主管主动创建的诊断进程必须原子归属Job。Windows自动启动的SPE入口仍按§18的OS入口前限制处理，不伪称可原子控制OS启动；owner在确认SPE助手实际身份后，把本次助手纳入同一诊断责任的Job/固定句柄清理集合，再ACK。不能归属或固定所有权就失败，不开始额外采集；该入口没有无Job继续转储fallback。结束确认覆盖同一责任全部从属对象，不能只看leader退出。所有权转移不得关闭唯一仍需保留的目标句柄。

验收增加SPE已持槽等待owner时的双向握手无死锁、从属读/哈希阻塞触发整体截止、全任务Job/固定句柄真实结束、迟到ACK/结果拒绝、并发第二通知拒绝、活动额度不重复授予，以及接管SPE Job失败的零新增采集。单飞责任释放和额度归零必须以实际结束为条件，不因线程future到期或异常finally释放。


### 19.2 PC007-R01/R02 作者修订（待同实例复审，不自关评议项）

1. **R01单飞及协议例外**：同一逻辑责任中，枚举、大文件读取/哈希、dump、证据验证/发布I/O任一时刻真正执行者至多1；上一执行者停止采集并移交唯一剩余额度/同一截止后，下一从属任务才能执行，不允许用同run/attempt名称掩盖多采集者。可并行的仅固定小报文握手收发与主管内存授权裁决，报文仍受现有16KiB上限、共同截止/额度约束，不含任意文件/命令，不持HTTP/状态/编排锁做潜在阻塞I/O。stop-intent的save/read/unlink和state/incident元数据同样不得在上述主管锁内等待文件I/O；主管只裁决身份完整的小结果，撤销内存权限不能等unlink完成，迟到文件不能恢复已撤销权限。所有并行协议工作也归本次Job/固定句柄清理集合，参与总资源峰值和实际结束门。
2. **R02逐对象结束**：助手/从属对象实际结束，只允许释放它自身的必要句柄，不能据此认定受管目标/树也已结束。目标或树内任一实际对象仍活，继续持有其必要观察/终止句柄并保持明确所有权。每个对象实际结束后可以释放对应句柄，无需为审计额外持有已结束对象；所有对象结束后进入恢复/全审计，审计通过才解除整体needs_recovery、failed/draining、单飞/额度责任及禁止新启动/替换的限制。管理员平台恢复必须以对象确定消失的实证为准，不能凭恢复命令返回假定消失。
3. **原生反例**：P05追加同责任内并发采集拒绝与协议握手并行的不同判据、全过程资源峰值；P03/P04追加“助手已结束但受管目标仍未结束”，确认目标句柄仍可观察/终止、未stopped/未放行新采集或替换、同主管只读仍报原始事实。可控用户态反例仍按产品故障门禁收敛，模拟平台未结束只测试失败保持、不授予平台归因资格。
