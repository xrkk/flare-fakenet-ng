# ipc-parent原件缺失根因与批次级IPC证据环境修复

会话角色: 作者/执行方

创建时间：2026-09-13（接58交接后）

## 失败现象

discovery100-03 sst-006 复验：restart 基线修复实机 7 项检查全部通过后，finalization 导出 run01 原件报 `SuiteError('complete VM run originals missing: ipc-parent.jsonl')`，整场景 fail，报告兜底分类 product_failure。

## 调查与证据

- guest 只读枚举（ipc-missing-investigation/guest-run-dir-listing.json）：run01 `54cbf722-cfb3-479a-a54d-051babea8255`、run02 `d84aef77-6b64-45d2-8441-f228e106ee18` 两个目录 `run.log`、`creation.jsonl`、`published.json`、`stdout_stderr.log` 等正常模式文件齐全，仅缺 `ipc-parent.jsonl`/`ipc-child.jsonl`；服务注册表 `Environment` 值不存在（env_present=false），服务 Running。
- 产品侧：`fakenet/mcp/managed.py::record_ipc` 仅当服务进程环境 `FAKENETNG_MCP_FAULT_INJECTION=1` 时写 `ipc-*.jsonl`；`fakenet/mcp/faultinject.py` 全部钩子要求 env **且** 已武装 `fault-injection.json`，env 单独启用不改变良性行为（仅增加证据记录）。产品默认关闭该 env 是 P04 既定设计。
- 执行器侧：`scenario_suite.py::_export_run_originals` 自执行器引入提交 `576c2fa`（2026-09-13 00:15）起对每个 run 无条件 `required={'run.log','ipc-parent.jsonl'}`；`_application_observation` TCP 分支用 `ipc-parent.jsonl` 做 `managed_identity`（managed PID/creation）归因，无降级路径。而套件仅在故障场景经 `_fault_mode(True)` 启用该 env（良性场景无任何预启）。
- 交叉验证：discovery100-01/02/03 三批全部 run 均无 `originals` 字段——良性导出从未成功过，01/02 被更早 body 失败掩盖（finalization 异常仅在 failure 为 None 时覆盖记录）。2026-09-12 spike-contract 良性导出（recovery-default，7 文件、无 ipc）早于 `576c2fa`，required 集当时不同，不构成反例。five-class-spike（故障 sst-001）导出含 ipc 文件，因 `_fault_mode(True)` 在场景内启用 env。

## 结论

执行器合同缺陷，**非产品生命周期缺陷**：套件要求每个 run 提供仅故障测试模式才记录的 IPC 原件，却从未为良性场景预启证据环境。100-03 的 product_failure 分类应修正为 evidence-side 执行器错误；run01/run02 产品侧产物完整。
