## 1. FIX-001：受管命令行读取缺少就绪条件（ACT-002）

历史 run 47e4fb8f-0c41-4202-b751-0b6cdf101812 的 creation.jsonl 已有 after_api/PID 6524/创建时间 134337313762636632，但没有 before_start；incident/exception.txt 为 managed start failed: OSError，WinError 299。代码 supervisor.start 在 ManagedProcess 返回后立即创建 ExitRetention；后者从固定目标句柄读取远程 PEB/ProcessParameters/CommandLine，之前没有子进程执行就绪握手。

本轮最小实机对照使用实际 exit_native.py、TargetHandle 原函数与原生 Win10 的短寿命 Python 子进程。40 次逐一创建，每次在同一个持有句柄上分别于刚创建和 stdout READY 后读取身份及命令行。刚创建 1/40 次失败 299；READY 后 0/40 次失败。失败样本 index 28、PID 4076、创建时间 134337353987005877，两个时点身份完全相同，单调时间 58168.3273421 与 58168.3481414；子进程正常退出 0。

证据支持：创建成功不足以保证当前远程命令行读取可用；进程已经执行到 Python 就绪点后，同一对象读取成功。排除该样本 PID 复用/已退出和持续性 ABI 不兼容。缺陷位于创建/读取的顺序合同，不应以固定 sleep、299 吞错或无限重试修复。

限制：实验目标为 C:\Python313\python.exe 3.13.7 x64，正式产品为随包受管映像；该实验不是产品修复后的证明，也未确定原历史 299 的具体三级 _read 子调用。方案应把正式随包原场景重验及就绪前退出/超时/错身份列为必要验收，不宣称所有 299 都源于同一原因。

## 2. FIX-002：未启动实例的停止分支缺失（ACT-002）

实际 managed.child_main 在 instance=None 时只接受 start/stacks 等；stop 被实例存在条件拦住。supervisor.start 在 ExitRetention 构造失败后仍执行统一 incident→stop；后者发送 stacks→stop。回放真实 child_main，仅替换 Windows/管道/实例构造边界，输入同 run seq1 stacks、seq2 stop，连续两次输出 managed operation not allowed in current state，退出 1，预期干净停止断言失败。

根因为父子生命周期阶段合同不一致。启动前停止应终结未接管子进程且不构造 FakeNet、不运行实例故障钩子；已有实例的停止仍执行原清理。该修复不应把失败启动改报成功，原 299 和 last_run_outcome=failed 必须保留。
