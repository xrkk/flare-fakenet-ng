## 问题一：reviewed-IP/process-redirect 配置全部无法启动（产品包装缺陷，已修复待部署）

- 现象：discovery100-05 中 sst-018..022（B2 重执行行）全部 `SuiteError('benign scenario did not publish healthy')`；产品 run.log：`CRITICAL Diverter Invalid EgressControl configuration` → `PolicyConfigError: reviewed IPv4 route checker is missing`（windows.py `_read_reviewed_ip_route_snapshots` → `_run_reviewed_route_checker` → `_run_route_checker`）。
- 根因：`fakenet/diverters/windows.py::_run_route_checker` 以 `__file__/../../` 查找仓库根的 `Test-ReviewedIPv4Routes.ps1`/`Test-ProcessRedirectRoutes.ps1`；冻结 onedir 下该路径解析到安装目录 `_internal/`，但 `fakenet-mcp.spec` 的 `datas=None` 从未打包这两个脚本（候选 zip 与 VM `C:\Program Files\FakeNet-NG-MCP` 均确认缺失，仅 install/uninstall ps1）。任何使用 reviewed IPv4 规则（B2 sink-and-reviewed-*）或 process-redirect 路由（B4）的渲染配置在初始化即崩——约40条场景被阻断，属产品包装缺陷，非执行器问题。
- 修复（产品，源提交 `514b2a9ab617357073dec354ad1339e8481ca97c`）：
  1. `fakenet-mcp.spec` datas 打包两个检查器脚本（落在冻结代码解析的 `_internal/` 根）；
  2. `windows.py::_run_route_checker` 增加 `sys._MEIPASS` 显式回退（冻结感知）；
  3. `tools/build_fakenetng_mcp_wine.py::verify_source` 增加两脚本必需校验。
- 构建与部署：Docker 固定镜像按不可变源提交重建（mcp-route-checker-fix-20260913-01），部署后需实机验证检查器存在并以最小 reviewed 配置生命周期验证启动。

## 问题二：五段恢复审计对临时 UDP 端口过敏（执行器，已修复）

- 现象：discovery100-04 sst-046（UDP 55346）与 discovery100-05 sst-023（UDP 53601）两次因 after 快照多出一个临时 UDP 监听被判 cleanup error → recovery_blocked 停批。两次端口均为临时段、事后已消失（55346 实查 Get-NetUDPEndpoint 0 结果），与记录56 Edge 临时端点同类：外部环境自然变化。
- 修复（执行器，`scenario_suite.py`）：新增 `_attribute_section_difference`——五段差异出现时立即以一次只读 VM 查询获取全部监听端点的属主（Win32_Process 名称/命令行）：
  - 属主为产品树（fakenetng-mcp*/managed/exit-monitor）或套件探针（命令行含 scenario-suite-20260912、scenario-probe-client）→ **仍为阻断性残留**（真实恢复责任不变）；
  - 端点已消失或属主为无关进程 → 记录为外部环境证据（difference_attribution + external/vanished），**不再判 cleanup error**；
  - 归因查询失败 → 保持原阻断差异（fail closed），不以差异字符串白名单豁免。
- 三处比较点全部接入：run-01 restart 恢复比对、活跃 run 停止后比对、finally 清理捕获。原 `_section_difference` 与产品恢复义务不变。
- 验证：离线 201 passed + 6 subtests（新增3回归：netstat 行解析含 IPv6、residue/external/vanished 分类、查询失败 fail closed）。
