## 0. 结论

本方案拟在 Windows `DomainAllowList` 模式中增加一个默认关闭的、单规则的 TCP 透明重定向能力：仅当一个新建 TCP 流被可靠归属于指定进程，且原始目标是指定公网 IPv4 `A` 时，FakeNet-NG 才把线侧目标地址改写为指定 RFC1918 私网 IPv4 `B`；来自 `B` 的对应返回流量在进入 Windows TCP 栈前把源地址恢复为 `A`。

期望合同如下：

```text
应用及 Windows TCP 栈看到：
    目标进程 P：本地地址:L  <->  公网 A:D

VM 专用网络线侧看到：
    目标进程 P：本地地址:L  <->  私网 B:D
```

端口 `D` 保持不变，本方案不做端口转换。只有同时完成正向 `A -> B` 和反向 `B -> A` 改写，才能维持应用所见的对端地址为 `A`。

该能力不等同于应用层代理，也不承诺 TLS、HTTP 或自定义协议完全无感。发往 `B` 的应用数据、TLS SNI、HTTP Host、证书校验目标和协议内容保持原样；`B` 侧服务必须自行提供与应用预期兼容的响应。

整体风险等级为**高**。最大不确定性是当前 WinDivert/PyDivert 网络层不直接提供 PID，必须通过 Windows IP Helper 的完整 TCP 连接元组解析进程归属，并在目标 VM 中先通过技术门禁证明首个 SYN 阶段的归属稳定性。

## 1. 需求解释与待确认假设

### 1.1 已明确需求

1. 当前只实现 Windows 版本；
2. 只对指定进程生效；
3. 当该进程访问指定公网 IPv4 `A` 时，将连接透明重定向到指定私网 IPv4 `B`；
4. 目标进程不应被要求修改自身配置、目标地址或调用方式；
5. 未经方案审核不得实施。

### 1.2 v0 为控制风险采用、但仍需审核确认的范围

1. 第一版只支持 TCP，不支持 UDP；
2. 第一版只支持一条进程重定向规则；
3. 规则覆盖 `A` 的全部 TCP 端口，原端口原样映射到 `B`，不增加端口转换；
4. 只从新的 `SYN=1, ACK=0` 流量建立映射，不接管 FakeNet-NG 启动前已经存在的连接；
5. 进程必须同时匹配规范化完整可执行文件路径和 SHA-256；仅 PID、仅文件名或仅源端口均不构成授权；
6. 子进程不自动继承父进程规则；由代理、共享网络服务或系统服务代发的连接按实际拥有 socket 的进程判断；
7. `A` 必须是经审核的公网全局单播 IPv4；`B` 必须是经审核的 RFC1918 私网 IPv4；
8. `B` 必须通过指定 VM 接口的稳定 on-link 路由可达，不允许经默认公网网关绕行；
9. 本方案只修改流量地址，不启动、不配置、不约束宿主机或 `B` 上的监听脚本；
10. 本方案不自动探测或选择 `A`、`B`、进程路径、进程哈希或端口；测试配置必须由审核后的构建 profile 固化；
11. 无法可靠取得进程归属、路由漂移、映射冲突或状态表耗尽时失败关闭，不连接真实 `A`。

上述任何假设被第三方或项目负责人否定后，都必须先升版方案并重新审核，不得在实施阶段自行扩大范围。

## 2. 目标与非目标

### 2.1 目标

1. 对指定进程发往精确公网 IPv4 `A` 的新 TCP 流执行双向地址转换；
2. 保持原协议、原本地地址、原本地端口和原目标端口，只改写对端 IPv4；
3. 目标进程通过 socket 查询所见的远端仍为 `A:D`；
4. `B` 侧服务在线侧收到的目标是 `B:D`；
5. 为每条连接建立有代际、容量、超时、关闭和端口复用保护的映射；
6. 进程归属必须使用完整 TCP 元组，并绑定 PID、进程创建时间、完整映像路径和审核身份；
7. 保持现有 DeepSeek 域名放行、域名 TLS relay、私网 takeover、指定公网 IP 放行、FakeNet 本地 diversion、双 PCAP 和停止恢复机制；
8. 所有拒绝、映射创建、正向改写、反向改写、过期、冲突和挂起均产生有界结构化日志；
9. 提供 Windows VM 一键验收脚本和无害测试客户端；
10. 默认配置不启用此功能，现有配置在未增加新字段时行为完全不变。

### 2.2 非目标

本方案不包含：

- Linux 实现或 Linux 动态验收；
- UDP、QUIC、IPv6、ICMP、非 TCP IP 协议、裸 socket、IPsec 或分片流量；
- TCP Fast Open 已携带数据首包的支持；
- CIDR、地址段、域名或运行时 DNS 结果作为重定向目标；
- 多条进程规则、规则热更新、父子进程自动继承或用户级规则；
- 端口转换、端口范围配置或协议识别；
- 修改 DNS、hosts、Windows 路由表、Windows 防火墙或宿主机网络配置；
- 启动、停止或管理 `B` 侧服务；
- TLS 解密、证书替换、SNI 改写、HTTP Host 改写或应用协议代理；
- 对 EDR、ETW、防火墙、抓包软件、时延检测或服务端指纹“无感”的保证；
- 把当前按源端口取得的 best-effort PID/进程名日志升级为通用安全授权能力；
- 在宿主机运行 FakeNet-NG 或执行真实恶意样本。

## 3. 当前代码基线与差距

### 3.1 Windows 捕获方向

`fakenet/diverters/windows.py::Diverter.__init__` 当前在 `DomainAllowList` 模式使用：

```python
outbound and (ip or ipv6)
```

因此只捕获出站包。现有 `Diverter._handle_policy_packet()` 也按外部出站裁决组织控制流，不能直接把来自 `B` 的入站返回包送入相同的出站失败关闭分支。

### 3.2 数据包改写能力

`WindowsPacketCtx` 已能把 `src_ip`、`dst_ip`、`sport` 和 `dport` 的修改同步写入 PyDivert packet；发送时由现有 PyDivert/WinDivert 路径负责校验和重算。这提供了地址改写基础，但当前没有针对远端 `B` 的双向映射合同。

### 3.3 当前进程归属不足以授权

`fakenet/diverters/winutil.py::get_pid_comm()` 当前只把数据包源端口传给：

- `_get_pid_port_tcp(port)`；
- `_get_pid_port_udp(port)`。

TCP 查询只比较本地端口；未比较本地地址、远端 `A`、远端端口和 TCP 状态。当前表缓冲区也按 512 行固定分配，而不是按 Windows 返回的所需大小动态重试。取得进程后只返回 basename，不返回稳定规范化路径。

这种实现适用于日志提示，不能作为将某一进程流量导向 `B` 的安全条件。

### 3.4 当前依赖边界

仓库使用 `wheelhouse/pydivert-2.1.0-py2.py3-none-any.whl`，绑定只公开 `NETWORK` 和 `NETWORK_FORWARD` 层；仓库内 WinDivert 驱动版本为 1.1.8。当前 packet address 只有接口、子接口和方向，没有 ProcessId。

因此 v0 不假定 WinDivert 能直接提供 PID。实施阶段必须先验证 Windows IP Helper 完整元组归属路径；如果门禁失败，停止实施并升版评估驱动/binding 升级，不得自动退回源端口匹配。

### 3.5 现有 NAT 不能直接复用

`fakenet/diverters/egresspolicy.py::RelayNatMapping` 管理的是允许域名到本地 TLS relay 的 TCP 映射，其反向键对应本地 relay，而非私网远端 `B`。本方案可以复用其代际、墓碑、限额和清理经验，但不能复用其类型、字典或域名 lease 前置条件。

## 4. 配置合同

### 4.1 配置位置

新字段继续放在 `[Diverter]`。FakeNet-NG 当前会把除 `[FakeNet]` 和 `[Diverter]` 以外的 section 视为 listener，因此 v0 不新增独立 INI section。

### 4.2 v0 单规则字段

```ini
ExternalProcessRedirectEnabled: No
ExternalProcessRedirectProtocol: TCP
ExternalProcessRedirectImagePath: __REVIEWED_PROCESS_IMAGE_PATH__
ExternalProcessRedirectImageSHA256: __REVIEWED_PROCESS_IMAGE_SHA256__
ExternalProcessRedirectOriginalIPv4: __REVIEWED_PUBLIC_IPV4_A__
ExternalProcessRedirectTargetIPv4: __REVIEWED_PRIVATE_IPV4_B__
```

合同说明：

1. `Enabled` 默认 `No`；其他字段在禁用时不得改变行为；
2. v0 的 `Protocol` 只接受精确 `TCP`，保留字段是为了避免以后用隐式默认扩大协议；
3. `ImagePath` 必须是 Windows 绝对路径，禁止环境变量、通配符、相对路径、目录和 NTFS alternate data stream；
4. `ImageSHA256` 必须是 64 位小写或大写十六进制，解析后规范化为小写；
5. `OriginalIPv4` 只接受单个公网全局单播 IPv4；
6. `TargetIPv4` 只接受单个 RFC1918 私网 IPv4；
7. 所有 TCP 端口 `1-65535` 均适用，目标端口保持不变；v0 不增加端口字段；
8. 不允许列表、重复键、多规则编码或运行时热更新。

### 4.3 启动验证

当 `Enabled: Yes` 时，必须在打开 WinDivert、修改 DNS或启动 listener 前完成：

1. 平台必须是 Windows；
2. `ExternalAccessPolicy` 必须是 `DomainAllowList`；
3. 所有必填字段必须存在且无空值；
4. 进程路径必须规范化并指向普通文件；文件 SHA-256 必须与配置一致；
5. `A`、`B` 必须满足各自地址类别，且 `A != B`；
6. `A` 和 `B` 均不得是 VM 本地地址或外部 DNS resolver；
7. `B` 不得是广播、组播、链路本地、回环、未指定、文档保留地址或其他特殊用途地址；
8. `B` 必须有精确、稳定、on-link 的 Windows route，路由源地址必须是 FakeNet 冻结的本地 IPv4，接口索引必须与审核 profile 一致；
9. `A` 不得同时出现在静态 `ExternalAllowedIPv4Rules` 中；静态冲突必须拒绝启动；
10. `B` 不得与 `ExternalTakeoverIPv4` 相同；v0 不允许两个机制共享同一私网目标；
11. 配置非法时整体启动失败，且不得留下 DNS、route、listener 或 WinDivert 状态变化。

对允许域名动态 DNS lease 与 `A` 的重叠无法在启动时完全预测，运行期优先级见第 8 节。

## 5. 进程身份合同

### 5.1 规则身份

配置身份由以下值共同构成：

```text
规范化最终映像路径 + 审核 SHA-256
```

文件名、命令行、父 PID、窗口标题、脚本路径或连接端口都不能单独构成身份。

### 5.2 运行期流身份

每个被授权的 TCP 流必须绑定：

- PID；
- 进程创建时间；
- 通过进程 handle 查询到的最终映像路径；
- 本地 IPv4和本地端口；
- 原始公网 `A` 和原始目标端口；
- 接口索引、子接口索引和方向；
- 映射 generation。

PID 仅是该组合的一部分，不能单独使用，以防 PID 重用。

### 5.3 Windows TCP owner 解析

新增 Windows adapter 应使用 `GetExtendedTcpTable(..., TCP_TABLE_OWNER_PID_ALL, ...)` 的完整 owner row：

1. 先取得所需缓冲区大小；
2. 按返回大小分配并处理 `ERROR_INSUFFICIENT_BUFFER` 重试；
3. 正确处理地址和端口字节序；
4. 使用本地地址、本地端口、远端 `A`、远端端口和可接受 TCP 状态匹配；
5. 结果为零条或多条时均视为不明确；
6. 取得 PID 后立即打开有限权限 process handle，查询创建时间和最终映像路径；
7. 路径、PID、创建时间在映射创建前再次复核；
8. 关闭所有 handle，不把逐包查询放入已建立流量路径。

### 5.4 首 SYN 技术门禁

当前实现尚未证明 WinDivert 截获首个出站 SYN 时，TCP owner table 中已经稳定存在完整 row。因此审核通过后的实施必须先完成一个不改变正式裁决的 VM 技术门禁：

1. 使用无害目标进程连续发起至少 100 个新 TCP 连接；
2. 每个首 SYN 都按完整元组查询 owner；
3. 记录零匹配、多匹配、错误 PID、查询失败和耗时；
4. 正确归属率必须为 100%，错误归属必须为 0；
5. P99 查询时延必须由第三方审核后设定阈值，v0 建议不超过 10 ms；
6. 若不能满足，停止正式实现并升版方案，不启用按端口、basename、命令行猜测或直接公网放行。

门禁测试代码属于实施内容，仍必须等本方案审核通过后才可编写。

### 5.5 已知身份限制

- 如果应用经代理、浏览器 broker、系统网络服务或其他进程代发，owner 是实际持有 socket 的进程，而不是业务发起者；
- 进程注入、内核驱动代理和具备更高权限的恶意代码不在本方案防护模型内；
- 配置文件哈希证明磁盘审核文件，但不能绝对证明每个运行页未被内存修改；
- 路径与哈希都匹配才授权；无法打开进程或查询最终路径时失败关闭。

## 6. 深模块与接口设计

### 6.1 外部 seam

新增 `ProcessRedirectEngine` 深模块，建议位于：

```text
fakenet/diverters/processredirect.py
```

该模块不得导入 PyDivert、ctypes、PowerShell 或 Windows DLL。它隐藏规则验证后的运行状态、正反向索引、generation、容量、超时、TCP 关闭状态、墓碑和裁决原因。

Windows Diverter 只需要了解一个小接口：

```python
decision = engine.classify_outbound(packet_tuple, owner_result)
decision = engine.classify_inbound(packet_tuple)
engine.observe_send_result(decision, sent)
engine.close()
```

`decision` 返回不可变结果，明确表达：不适用、放行未修改、正向改写、反向恢复、拒绝及原因。调用方不直接读写内部映射字典。

### 6.2 Windows 进程归属 seam

定义只供 engine/Windows adapter 使用的 owner resolver 接口：

```python
resolve_tcp_owner(original_flow) -> OwnerResolution
```

存在两个 adapter：

1. 生产 adapter：Windows IP Helper + process handle；
2. 测试 adapter：确定性内存结果，用于覆盖 PID 重用、歧义和错误。

接口返回明确的 `MATCH`、`NO_MATCH`、`AMBIGUOUS` 或 `ERROR`，不得用 `None` 混淆不同失败原因。

### 6.3 不采用的设计

以下设计在 v0 中明确拒绝：

- 把进程字段直接塞入现有 `RelayNatMapping`；
- 在多个 Windows callback 中分别维护正向和反向字典；
- 每个数据包重新扫描 TCP owner table；
- 用当前 `_get_pid_port_tcp(source_port)` 结果作为授权；
- 用进程 basename 白名单作为授权；
- 用 Windows 防火墙、route 或 hosts 替代逐进程重定向；
- 在重定向失败后继续访问真实 `A`。

采用深模块的原因是把复杂状态和失败合同集中在一个 interface 后，使 Windows packet adapter、测试和日志调用方不需要理解内部 NAT 生命周期。

## 7. 双向 NAT 状态模型

### 7.1 映射字段

每个映射至少包含：

```text
generation
protocol = TCP
local_ipv4, local_port
original_ipv4 = A, original_port
redirect_ipv4 = B, redirect_port = original_port
interface_index, subinterface_index
pid, process_creation_time, normalized_image_path
created_at, last_seen_at, hard_expires_at
tcp_state, client_fin_seen, server_fin_seen
```

SHA-256 属于冻结规则身份，不需要在每包对象中重复保存，但映射必须引用不可变规则 generation。

### 7.2 索引

至少维护：

- 正向键：`TCP/local_ip/local_port/A/original_port/interface`；
- 反向键：`TCP/B/original_port/local_ip/local_port/interface`；
- 客户端端点键：`TCP/local_ip/local_port/interface`；
- generation 索引；
- 正向、反向及客户端端点墓碑。

不允许同一客户端端点同时绑定不同目标或 generation。冲突时拒绝新映射。

### 7.3 建立

1. 只在出站新 SYN 上尝试 owner 解析；
2. 原始目标必须精确等于 `A`；
3. owner 必须明确匹配审核进程；
4. route 与接口快照必须仍有效；
5. 没有活动映射或墓碑冲突；
6. 容量和每进程限额未超限；
7. 原子创建正向、反向和 generation 索引；
8. 将该包 `dst_ip` 从 `A` 改为 `B`，端口不变；
9. 发送失败时立即删除活动映射并写入墓碑。

相同 SYN 重传必须命中同一个 generation，不能重复创建。

### 7.4 已建立流正向处理

后续 `local -> A` 包按完整正向键命中映射，不再逐包查询进程。命中后把 `dst_ip` 改为 `B`。接口、原地址、端口或 generation 不匹配时拒绝。

### 7.5 反向处理

来自 `B` 的入站 TCP 包：

1. 命中活动反向映射：把 `src_ip` 从 `B` 改为 `A` 后重注入；
2. 命中墓碑或与活动客户端端点冲突：丢弃并记录迟到包；
3. 完全不属于任何映射或墓碑：原样重注入，以免破坏 VM 中其他合法的直接 `B` 连接；
4. 接口或端口与映射不符：不得猜测匹配。

### 7.6 关闭与清理

- 任一方向 RST：立即关闭活动映射并建立墓碑；
- 双向 FIN 完成：关闭并建立墓碑；
- 单边 FIN：保留到对端 FIN 或短关闭超时；
- 空闲超时：v0 建议 300 秒；
- 硬超时：v0 建议 3600 秒，避免恶意保活永久占用；
- FakeNet 停止、WinDivert 接收线程异常、route 挂起：关闭全部映射；
- 容量建议沿用有界思路，初始上限 1024 活动映射、单 PID 256；最终数值需审核确认并通过压力测试。

墓碑时长必须覆盖 Windows 常见端口快速复用和迟到包窗口，v0 建议 60 秒；第三方应重点审查该数值与现有 relay 墓碑是否一致或需要区分。

## 8. WinDivert 捕获、优先级与重注入

### 8.1 捕获过滤器

功能禁用时，过滤器字节级保持现状。

功能启用时，在现有全部出站捕获之外，只增加精确的 IPv4 入站 `src == B` 分支。不得捕获全部入站 IPv4/IPv6。过滤器必须由已验证的规范化 `B` 生成，不拼接未验证输入。

### 8.2 方向分流

`_handle_policy_packet()` 在构造 `WindowsPacketCtx` 后必须先按方向分流：

- 入站且 `src == B`：只进入反向映射处理；
- 出站：继续进入现有策略链，并在规定位置调用进程重定向；
- 任何意外方向或地址：失败关闭或原样重注入必须由明确裁决给出，禁止落入出站默认分支。

### 8.3 出站优先级

建议优先级：

1. 已登记的内部 DNS/TLS relay control permit；
2. 现有 domain relay 本地返回修复；
3. **目标 `A` 的进程归属门禁和进程重定向**；
4. takeover sink；
5. 已存在 domain relay mapping 或允许域名新 SYN relay；
6. reviewed public IPv4 direct allow；
7. 现有 FakeNet diversion 或外部失败关闭。

规则含义：

- 对 `A` 的流量必须先得到明确 owner 结果；
- owner 匹配目标进程时重定向 `B`；
- owner 明确为其他进程时继续现有策略；
- owner 为 `NO_MATCH`、`AMBIGUOUS` 或 `ERROR` 时丢弃，不允许继续命中域名 relay、reviewed IP 或真实公网路径；
- 这样既防止目标进程在归属失败时访问真实 `A`，又允许明确属于分析工具的 DeepSeek 流量继续走现有域名策略。

### 8.4 防止重注入循环

- 出站重写后目标已是 `B`，不再命中出站 `dst == A` 的重定向条件；
- 入站恢复后源已是 `A`，不再命中入站 `src == B` 的过滤条件；
- 测试必须证明单个包只发生一次方向性改写；
- 若过滤器或重注入行为导致再次捕获，必须失败并升版方案，不能以循环计数阈值掩盖。

## 9. 路由与运行期漂移

### 9.1 启动 route 快照

启动时冻结：

- `B` 的最佳 route；
- destination prefix；
- `NextHop=0.0.0.0`；
- 本地源 IPv4；
- interface index/alias；
- route metric 和 interface metric。

要求 route 是比默认路由更具体的 on-link 路由，源地址属于 VM，且 `B` 不是 VM 自身地址。

### 9.2 运行期复核

在首次建流前复核 route 快照；运行中由有界 watchdog 周期复核。下列变化挂起重定向并关闭活动映射：

- 最佳 route、源地址或接口变化；
- `B` 变成本地地址；
- route 转为默认网关或非 on-link；
- 网络接口消失或地址漂移。

挂起期间所有需要进程归属的 `A` 流量均丢弃，不回退真实 `A`。恢复必须满足完整快照重新验证并记录新 generation，不能仅凭一次 ping 或端口探测自动恢复。

本方案不要求端口存活探测；端口未监听只表现为连接失败，不影响地址重定向合同。

## 10. TLS 和应用层边界

重定向只修改 IPv4 地址：

- TLS ClientHello、SNI、ALPN 和证书验证逻辑不变；
- HTTP Host、代理 CONNECT 目标和应用 payload 不变；
- 如果程序使用域名发起连接，DNS 仍按现有策略处理；本规则只看最终出站目标是否为 `A`；
- 如果程序使用字面量 IP，SNI 可能缺失，但程序仍可能验证证书中的 IP SAN；
- `B` 返回的 TCP 序列号、ACK、窗口和 payload 必须与连接状态兼容，NAT 不修改这些字段。

因此验收中的“无感”限定为：目标应用无需更改目标地址，且成功连接后 socket 远端仍显示 `A:D`。不能把 TLS 成功作为纯网络改写必然结果；TLS 正向用例需要 `B` 侧测试服务提供审核后的兼容证书/协议，或者使用无 TLS 的无害 sentinel 协议验证 NAT 本身。

## 11. 失败关闭与 fallback 声明

### 11.1 失败关闭

以下情况不得建立或继续映射：

- 配置或地址验证失败；
- owner row 不存在、多条匹配或 Windows 查询错误；
- PID 已退出、创建时间变化或映像路径不匹配；
- route/interface 漂移；
- 状态表达到总量或单进程上限；
- generation、端点或墓碑冲突；
- 分片、非 TCP、IPv6、异常 TCP flags 或不支持的首包；
- WinDivert send 失败、watchdog 失败或策略关闭。

### 11.2 fallback

**本方案没有添加任何未显式请求确认的运行时 fallback。** 特别是：

- 不回退到真实公网 `A`；
- 不回退到按源端口、basename 或 PID-only 识别；
- 不回退到自动把该连接交给 FakeNet 默认 listener；
- 不回退到 takeover 地址或其他私网地址；
- 不自动升级 WinDivert、切换 WFP 或修改系统 route/firewall；
- 不在 `B` 不可达时选择其他目标。

如果首 SYN 进程归属技术门禁失败，唯一允许的动作是停止实施、记录证据并升版方案重新审核。该动作是实施门禁，不是运行时 fallback。

## 12. 日志与 PCAP 证据

### 12.1 结构化事件

建议新增并限速：

- `PROCESS_REDIRECT_MAPPING_CREATED`；
- `PROCESS_REDIRECT_FORWARD`；
- `PROCESS_REDIRECT_REVERSE`；
- `PROCESS_REDIRECT_CLOSED`；
- `PROCESS_REDIRECT_DROP`；
- `PROCESS_REDIRECT_SUSPENDED`；
- `PROCESS_REDIRECT_RESUMED`；
- `PROCESS_REDIRECT_AUDIT_SUMMARY`。

事件包含 generation、协议、原/目标地址端口、PID、规范化进程标识摘要、接口、原因和计数；不记录 payload、完整命令行或其他敏感进程环境。

每包成功日志必须有界：首次流详细记录，后续按周期输出 packet/byte/flow 汇总，避免恶意流量造成无限日志增长。

### 12.2 PCAP 语义

保持现有 `write_pcap` 合同：初始包和被改写后的包可按现有调用次数分别记录。新增路径要求：

- 正向首包先记录 `dst=A` 的原始形态，再记录 `dst=B` 的改写形态；
- 反向包先记录 `src=B` 的原始形态，再记录 `src=A` 的恢复形态；
- 原始 RAW 与 Ethernet converted PCAP 继续逐记录一致；
- generation 关联依赖结构化日志，不向 PCAP 注入私有 metadata；
- 独立 pktmon/系统抓包仍是判断线侧是否实际访问 `B`、是否误访问 `A` 的验收依据。

若新增入站写入破坏双 PCAP 的数量、顺序或停止完整性，应视为阻断缺陷。

### 13.3 Windows VM 动态验收

只在已拍快照的目标 VM 中运行，宿主机严禁运行 FakeNet-NG。验收包包含源码可审阅的无害 TCP 客户端和一键 `.cmd` 脚本；不使用恶意样本。

测试角色：

1. 目标客户端：路径和哈希匹配规则，连接字面量 `A:D`；
2. 非目标客户端：行为相同但映像路径不匹配；
3. `B:D` sentinel：由测试环境外部预置，返回包含本次随机 nonce 的响应；FakeNet-NG 不负责启动；
4. 独立 pktmon：记录 VM 线侧证据。

一键脚本不得要求操作者输入 DNS、A、B、进程路径、哈希或端口；这些值必须由审核后的版本 profile 固化。脚本执行后直接生成明文日志，不压缩日志。

### 13.4 动态通过条件

1. 首 SYN owner 技术门禁满足第 5.4 节；
2. 目标客户端连接 `A:D` 成功并收到 `B` sentinel nonce；
3. 目标客户端 `getpeername()` 精确返回 `A:D`；
4. pktmon 证明线侧出现 `VM -> B:D` 及 `B:D -> VM`，没有 `VM -> A:D`；
5. FakeNet 日志具有相同 generation 的正向和反向事件；
6. 非目标客户端不被导向 `B`，且仍遵守现有外部策略；
7. owner 不明确时连接失败，pktmon 证明既未访问 `A` 也未访问 `B`；
8. `B` 不监听/不可达时目标客户端失败，且没有 `A` fallback；
9. 并发、重传、RST、双 FIN、空闲超时、端口复用和进程退出结果符合状态合同；
10. 直接访问 `B` 的其他合法连接不因新增入站 filter 被破坏；
11. DeepSeek、takeover、reviewed IPv4 和 FakeNet 默认 diversion 回归通过；
12. Ctrl+C 停止后 WinDivert、listener、DNS、route 快照和日志均正常收尾；
13. 双 PCAP 启用 profile 下原始/converted 文件均通过现有验证器；
14. 测试完成后系统网络状态与测试前一致。

2. 代码回滚：回退独立功能提交；
3. VM 运行回滚：停止 FakeNet-NG、关闭 WinDivert handle、清空内存映射并执行现有 DNS/网络恢复；
4. 不修改持久 route/firewall/hosts，因此不设计这些系统状态的回滚。

回滚不是运行时 fallback；活动会话中发生安全错误时必须失败关闭并停止/恢复，不能动态切回真实 `A`。

## 17. 风险清单

| 风险 | 等级 | 控制措施 |
|---|---:|---|
| 首 SYN 无法稳定取得 PID | 严重 | 先做 100% 技术门禁；失败则停止并升版 |
| 仅端口匹配导致错误进程被重定向 | 严重 | 完整 TCP 元组、路径、创建时间；禁止端口 fallback |
| PID 重用或端口快速复用 | 高 | 创建时间、generation、客户端端点唯一性、墓碑 |
| 返回包未改写或错误改写 | 高 | 精确反向键、接口绑定、VM 双向 pktmon 证据 |
| 入站 filter 破坏其他 `B` 连接 | 高 | 只捕获 `src=B`；无映射且无墓碑时原样重注入 |
| 与 DeepSeek/domain relay 优先级冲突 | 高 | `A` 先归属；匹配进程重定向，明确其他进程继续现有策略，未知则丢弃 |
| `B` route 漂移至错误网卡/网关 | 高 | 启动冻结、运行复核、on-link 合同、挂起失败关闭 |
| TLS/协议不兼容导致“无感”失败 | 高 | 明确网络层边界；sentinel 验 NAT，TLS 另做有条件用例 |
| 状态表或日志被恶意流量耗尽 | 高 | 总量/单 PID 限额、超时、墓碑、首流日志与汇总限速 |
| WinDivert 重注入循环 | 高 | 地址变化后精确 filter 不再命中；循环测试为阻断门禁 |
| 进程通过 broker/proxy 发流 | 中至高 | 按实际 socket owner；明确非目标，不猜测业务来源 |
| 进程路径文件被替换 | 中至高 | 启动哈希、运行路径和进程创建身份；披露不证明内存页 |
| Windows 功能影响 Linux | 中 | Windows adapter隔离、默认关闭、Linux导入回归 |
| PCAP 记录语义被破坏 | 中 | 改写前后成对记录、双 writer 回归、pktmon 独立证据 |
| B 服务未监听 | 中 | 不做 fallback；连接失败，日志和 pktmon 证明目标仍是 B |

## 18. 第三方审核重点

第三方不能只检查“是否把 `dst_ip` 改成 `B`”，应重点审核：

1. **进程归属可行性：** WinDivert 1.1.8/PyDivert 2.1.0 没有 PID 的事实是否处理正确；完整 TCP owner row 在首 SYN 的门禁是否足够；
2. **进程身份强度：** 路径、SHA-256、PID、创建时间和完整元组是否存在 TOCTOU、PID 重用或别名绕过；
3. **双向状态正确性：** 正向/反向键、generation、SYN 重传、FIN/RST、迟到包、端口复用和墓碑；
4. **入站捕获安全：** filter 是否只扩大到 `src=B`；无映射的合法 B 流量是否保持；是否可能形成重注入循环；
5. **策略优先级：** 目标 `A` 与允许域名动态 lease、DeepSeek、takeover、reviewed IP、FakeNet diversion 的交互是否符合第 8.3 节；
6. **失败关闭：** owner 未知、route 漂移、状态耗尽、send 失败和 B 不可达时是否绝无真实 A fallback；
7. **route 约束：** B 是否确实为审核 RFC1918、on-link、指定接口，是否可能经默认网关或其他网卡；
8. **应用层边界：** “无感”是否被准确限定，是否错误承诺 TLS 证书、SNI 或协议兼容；
9. **性能与拒绝服务：** owner 查询是否只在新 SYN、缓冲动态分配是否有上界、状态和日志是否有界；
10. **停止与异常恢复：** WinDivert receiver、watchdog、PCAP fatal、Ctrl+C 和启动失败路径是否都能关闭映射和恢复网络；
11. **验收证据：** 目标/非目标进程、`getpeername=A`、sentinel nonce、线侧只有 B、没有 A、并发/复用/故障回归是否都可自动判读；
12. **范围纪律：** 是否意外实现 UDP、端口转换、多规则、子进程继承、驱动升级、宿主机监听器管理或 Linux 功能；
13. **fallback 审计：** 是否存在隐藏的按端口匹配、basename匹配、真实公网直连或通用 listener 降级；
14. **方案可落地性：** VM 是否具备审核后的 A/B、B sentinel、管理员运行 WinDivert 的条件及两个可区分的无害客户端映像。

审核者应把任何需要升级 WinDivert、引入 WFP、支持 UDP 或放宽进程身份的建议视为方案范围变化，要求升版后重新审核，而不是作为实现细节直接接受。

## 21. v1 增量合同：重评估修订

### 21.0 v1 结论与风险等级

v1 将总体风险由 v0 的“高”修订为：**严重，且在两个实施前技术门禁通过前，可行性尚未闭合**。

两个前置门禁分别是：

1. 目标 VM 中首 SYN 的完整 TCP owner 归属必须在顺序、并发和压力条件下保持零错误归属；
2. 公网 `A` 与私网 `B` 必须使用同一个冻结本地源 IPv4和接口索引；WinDivert 实际捕获到的子接口索引按流冻结并在返回方向复核。

任一门禁失败都不是普通测试失败，而是当前 v1 实现路线不成立。此时必须停止实施并升版重新审核；不得在实施中增加源地址 NAT、启用 weak-host、升级 WinDivert、引入 WFP、降低进程身份强度或连接真实 `A`。

### 21.1 网络拓扑合同：同源地址、同接口

v0 第 1.2、4.3、7、8、9 节中仅要求 `B` on-link 可达的表述不完整。v1 以本节替代冲突内容。

#### 21.1.1 启动双 route 快照

启动时必须以只读方式分别取得 `A` 和 `B` 的最佳 IPv4 route，并冻结：

- 最佳本地源 IPv4；
- interface index、interface alias；
- destination prefix、next hop；
- route metric、interface metric；
- 相关接口的 `WeakHostSend`、`WeakHostReceive` 状态；
- 本地地址的 DAD/有效状态和 `SkipAsSource` 状态。

必须同时满足：

```text
BestSource(A) == BestSource(B)
InterfaceIndex(A) == InterfaceIndex(B)
BestSource(A/B) 是 VM 当前有效本地 IPv4
B 的 route 是比默认路由更具体的 on-link route
相关接口 WeakHostSend == Disabled
相关接口 WeakHostReceive == Disabled
```

v1 不修改 weak-host、route、接口或本地地址；任一条件不满足即拒绝启动。方案不依赖 Windows weak-host 行为来跨网卡发送或接收。

#### 21.1.2 逐流复核

每个发往 `A` 的新 SYN 还必须满足：

```text
packet.src_ipv4 == FrozenBestSource(A/B)
packet.interface_index == FrozenInterfaceIndex(A/B)
packet.subinterface_index 被记录为该映射的 FrozenFlowSubInterfaceIndex
```

应用显式绑定其他本地 IPv4、VPN/route 改变源地址、接口重连导致索引变化时，该流失败关闭。不得把原始本地地址改写成另一个接口地址。

来自 `B` 的返回包必须同时满足：

```text
packet.dst_ipv4 == FrozenBestSource(A/B)
packet.interface_index == FrozenInterfaceIndex(A/B)
packet.subinterface_index == mapping.FrozenFlowSubInterfaceIndex
```

不满足时不得按映射猜测改写。

#### 21.1.3 明确拒绝源地址 NAT

v1 只执行：

```text
正向：L:S -> A:D  改为  L:S -> B:D
反向：B:D -> L:S  改为  A:D -> L:S
```

其中 `L` 在两个方向及 A/B 两条 route 上完全相同。以下双端 NAT 不属于 v1：

```text
L1:S -> A:D  改为  L2:S -> B:D
B:D -> L2:S  改为  A:D -> L1:S
```

如果目标 VM 只能使用第二种拓扑，必须另立方案；不得把它作为当前实现细节加入。

### 21.2 运行保证与停止/崩溃边界

v0 的“不回退真实 A”表述需要增加时间边界。v1 的强制保证是：

> 只有在 FakeNet-NG 进程存活、WinDivert handle 已健康打开、接收线程仍在裁决且重定向策略未关闭期间，目标 `A` 流量才保证被重定向或丢弃，不会主动回退真实 `A`。

WinDivert handle 关闭后，Windows 恢复正常网络路径；仍存活的目标进程可能继续或重传到真实 `A`。v1 不得宣称应用崩溃、FakeNet 进程被强制结束、系统断电、驱动卸载或 handle 关闭后的持久失败关闭。

#### 21.2.1 受控停止

- 一键验收 runner 必须拥有无害目标客户端的进程 handle；
- runner 必须先请求客户端退出并确认 PID/创建时间对应的进程已经终止，再停止 FakeNet-NG；
- 客户端未退出时 runner 不得把网络恢复后的结果标为安全通过；
- runner 超时后必须记录 `TARGET_PROCESS_STILL_RUNNING`，验收失败，并明确提示继续运行会存在真实 A 泄漏风险；
- 正式恶意样本的生命周期不由 FakeNet-NG 擅自终止。操作者或上层沙箱必须先停止样本，再停止 FakeNet-NG；该外部操作前提必须写入交付 README 和启动日志。

#### 21.2.2 非受控退出

当前范围不增加持久 Windows Firewall、WFP callout、hypervisor egress rule 或独立守护进程，因此无法对 FakeNet 进程被强制终止后的 A 流量提供 kill-switch。若项目要求“FakeNet 崩溃后仍绝不访问 A”，该要求会扩大授权和系统修改范围，必须另立方案。

#### 21.2.3 日志措辞

`WinDivertSend()` 返回成功只表示注入调用成功，不得记录为“B 已收到”或“线侧发送成功”。只有独立 pktmon 和 B sentinel 可以构成线侧/端到端证据。

### 21.3 进程归属与身份修订

#### 21.3.1 owner 结果枚举

v0 第 6.2、8.3 节的 `MATCH/NO_MATCH` 表述被以下合同替代：

- `RESOLVED`：唯一解析到一个实际 owner，结果携带 PID、进程创建时间和最终映像身份；
- `NOT_FOUND`：完整 TCP row 不存在；
- `AMBIGUOUS`：存在多条候选或无法唯一绑定；
- `ERROR`：Windows API、权限、缓冲区、路径或进程查询失败。

`RESOLVED` 后再由冻结规则判断为“目标进程”或“明确的非目标进程”。不得用 `None` 同时表示这些状态。

#### 21.3.2 严格 resolver 与现有日志隔离

严格 resolver 必须新增独立 Windows adapter。不得直接改变现有 `get_pid_comm()`、`_get_pid_port_tcp()` 或依赖它们的 best-effort 日志语义。共享底层表枚举代码时，也必须由回归测试证明旧 interface 的返回和错误合同未变化。

严格 resolver 使用完整 IPv4 TCP owner row，并明确披露：Windows owner PID 表示对该连接执行 context bind 的 PID；socket 复制、继承、broker、代理、进程注入和共享宿主可能使它不同于业务代码的原始发起者。

#### 21.3.3 映像路径规范化

v1 固定使用 Unicode Win32 最终映像路径，不使用 ANSI basename。规范化至少处理：

- 大小写与路径分隔符；
- `\\?\` 前缀；
- DOS drive path 与 native device path 的转换；
- `.`、`..`、短路径、符号链接和 junction；
- volume serial number 与 file ID；
- 文件在启动验证与进程查询之间被替换、删除或变成 hard link 的情况。

启动时对审核路径打开文件 handle，基于该 handle 取得最终路径、文件身份和 SHA-256；运行期 owner 必须匹配审核后的最终路径及文件身份。无法复核时失败关闭。

#### 21.3.4 共享运行时限制

Python、PowerShell、rundll32、mshta、svchost、浏览器 broker 等共享宿主场景只能识别实际 socket owner 的可执行映像，不能可靠识别其中的脚本、DLL、标签页或业务 payload。若目标与正常工具共用同一审核映像路径和文件身份，v1 不具备区分能力，必须拒绝该 profile；不得改用命令行字符串作为隐式替代授权。

### 21.4 owner 查询性能与拒绝服务门禁

v0 的“100 个连接、P99 建议 10 ms”不足以证明热路径安全。v1 以本节替代第 5.4 节的数量和性能合同。

#### 21.4.1 运行时查询预算

- owner 查询只允许发生在 `dst=A`、TCP、`SYN=1,ACK=0` 且没有现有映射的包；
- 同一完整 SYN 元组的重传必须共享短期查询结果，不得重复扫描表；
- 对 A 的 owner 查询使用有界 token bucket；超过预算的新 SYN直接失败关闭，不排队、不查询、不进入现有域名或公网放行路径；
- 进程映像身份按 `(PID, creation_time, file_id)` 有界缓存，TCP owner row 仍逐新流唯一解析；
- 缓存必须有最大条目、短 TTL和进程退出清理，不能跨 PID 创建时间复用；
- owner 查询、路径查询和哈希复核不得发生在已建立流的逐包路径。

预算的最终数值必须由 VM 压力证据确定并经第三方审核，不能在实现阶段任意填写。

#### 21.4.2 扩大技术门禁

至少覆盖：

1. 五次干净 VM 快照启动；
2. 每次同时包含目标进程、明确非目标进程和 owner 查询失败注入；
3. 不少于 10,000 个总 TCP 新流；
4. 至少 64 个并发新流；
5. SYN 重传、端口复用、PID 退出/重用和进程路径替换；
6. 对 A 的受控 SYN 洪泛，证明查询预算生效且内存/日志有界；
7. 洪泛期间 DeepSeek DNS、TLS relay、takeover、reviewed IP 和普通 FakeNet diversion 的延迟与成功率回归；
8. 目标 VM 当前 Defender、EDR、VPN 和其他 WFP 驱动共存状态；
9. 零错误归属、零错误重定向、零真实 A 线侧包；
10. WinDivert queue drop、receiver lag、CPU、内存和日志增长均在审核阈值内。

正常负载下允许 `NOT_FOUND` 的比例也必须由审核明确；无论比例如何，错误归属和错误重定向都必须为零。

### 21.5 深模块 interface 修订

v0 的 `classify_outbound(packet_tuple, owner_result)` 把“何时查 owner”和 owner 结果传递顺序暴露给调用方，深度不足；`observe_send_result(decision, sent)` 也没有定义 exactly-once 和异常事务。v1 替换为：

```python
prepared = engine.prepare(packet_tuple)
try:
    # Windows adapter仅按不可变decision执行改写与WinDivertSend。
    outcome = send(prepared.decision)
except BaseException as exc:
    engine.abort(prepared.token, reason=type(exc).__name__)
    raise
else:
    engine.commit(prepared.token, outcome)

engine.close(reason)
```

接口合同：

- engine 构造时注入严格 owner resolver、单调 clock 和不可变审核规则；
- engine 内部决定只有新 A SYN 才调用 resolver；Windows caller 不提供 owner_result；
- `prepare()` 同时处理出站和入站，方向属于 packet tuple；
- 返回不可变 decision 与一次性 token；
- 映射创建、TCP 状态变化、FIN/RST和墓碑变更在 commit/abort 后原子完成；
- `commit()`、`abort()` 对 token exactly-once，重复或未知 token 是失败关闭错误；
- pending token 有严格容量和短超时，engine.close 会原子 abort 全部 pending并关闭活动映射；
- send outcome 只区分注入调用结果，不宣称线侧送达；
- 测试 adapter 提供 owner resolver、clock和send outcome，以 engine interface 作为主要测试面。

Windows adapter 不得直接读写 engine 内部映射、墓碑、计数或 TCP 状态。

### 21.6 映射生命周期修订

- v0 建议的固定 60 秒墓碑不再视为已批准数值；
- 墓碑必须覆盖目标 VM 中同一 TCP 四元组可安全复用前的窗口，并通过端口复用/迟到包实测确定；
- idle timeout、half-close timeout和hard timeout也必须由 VM 长连接测试确定并经第三方审核；
- hard timeout到期会破坏应用层透明性，必须记录明确事件并让验收客户端验证可观察行为；
- 不得仅以客户端端点 `(local_ip, local_port)` 阻止所有其他远端连接；索引应尽量使用完整正反向元组，只有能证明反向歧义时才增加更宽的端点互斥；
- send调用失败后的墓碑与正常TCP关闭墓碑应区分原因和时长，避免一次瞬时注入错误无依据地阻止长时间重连；
- 迟到 B 包只有在命中活动映射或已知墓碑时才能改写/丢弃；无状态猜测禁止。

### 21.7 全端口重定向的宿主机暴露

v1 保持“全部 TCP 端口、端口不转换”的范围，但新增强制风险声明：

```text
A:1-65535  会映射为  B:1-65535
```

因此目标进程可能接触 B 上的 SMB、RDP、WinRM、数据库、调试器、管理端口及任何其他宿主机服务。这是全端口合同的直接结果，不由 FakeNet-NG限制或缓解。项目负责人和第三方必须明确接受该风险；未接受则应另行把范围改成审核端口集合并重新审核，而不是在实现中暗加端口限制。

### 21.8 与现有策略的隔离和兼容性透传

#### 21.8.1 目标 A 的 owner 门禁

对所有发往精确 `A` 的新 TCP SYN：

1. `RESOLVED` 且身份匹配目标进程：进入重定向；
2. `RESOLVED` 且明确为其他进程：继续既有 domain relay、reviewed IP、FakeNet diversion或失败关闭裁决；
3. `NOT_FOUND`、`AMBIGUOUS`、`ERROR`、查询预算耗尽：立即丢弃，不继续其他真实出口路径。

第 2 项是**明确非目标进程兼容性透传**，不是失败 fallback。它可能允许明确非目标的分析工具继续访问与 A 重叠的 DeepSeek/允许域名 IP；其正确性完全依赖 owner 唯一解析。第三方必须审查这一可用性与安全性取舍。

### 21.8.2 独立挂起状态

进程重定向的 route、owner budget、状态表或 watchdog 故障只允许挂起 `ProcessRedirectEngine`。不得调用会同时挂起允许域名、DNS/TLS relay、takeover 或 reviewed IPv4 的全局 `egress_policy.suspend()`，除非检测到的是现有策略共同依赖的本地地址总快照失效。

新模块必须拥有自己的：

- `available/suspended/closed` 状态；
- suspend reason 与 generation；
- route 快照和复核结果；
- 审计摘要；
- 关闭和恢复合同。

恢复必须重新验证 A/B 双 route、同源/同接口、weak-host、进程审核文件身份及本地地址快照。恢复只创建新 engine generation，不恢复旧 NAT 映射。

#### 21.8.3 保留旧进程日志 interface

现有日志继续可以使用不可靠的 basename/source-port提示，但任何日志字段都不得被误标为新重定向授权证据。严格 owner resolver 使用不同函数名、不同结果类型和独立测试。

### 21.9 入站 B 捕获和 WFP 共存

#### 21.9.1 精确 filter

启用时只增加：

```text
inbound and ip and tcp and src == B and dst == FrozenLocalIPv4
```

并保留现有出站 filter。还应尽可能把 TCP、地址和本地目标放入内核 filter，避免把 B 的无关协议送进用户态。

#### 21.9.2 三类入站结果

1. 命中活动反向映射：`src B -> A` 后重注入；
2. 命中映射墓碑：丢弃迟到包；
3. 完全不属于映射/墓碑：原样重注入，保持其他直接 B 连接。

第 3 项是**未映射 B 流量兼容性透传**，不是为目标流选择其他目的地的 fallback。它是避免破坏现有 B 连接所必需，但存在与其他 WFP callout 驱动反复拦截/重注入的风险。

#### 21.9.3 共存阻断门禁

- 必须证明同一 FakeNet WinDivert handle 不会再次收到自己在同一 priority 重注入的未修改 B 包；
- 必须在目标 VM 当前 Defender、EDR、VPN和其他已安装网络驱动保持启用的状态下测试；
- 监控 `ERROR_HOST_UNREACHABLE`、TTL异常变化、重复 packet hash、重复时间戳和异常 CPU；
- 若未修改 B 透传形成循环、重复捕获或不可接受延迟，v1 阻断；不得通过忽略错误、修改 TTL或关闭安全软件把验收标为通过；
- 新增第二个 WinDivert priority/handle、升级驱动或使用 Impostor 元数据均属于方案变化，需升版审核。

### 21.10 PCAP 与审计语义修订

FakeNet 内建 PCAP 是**策略观察记录**，不是线侧单包抓取。v1 必须在 README 和日志开头说明：

- 同一正向包可能以 `dst=A` 和 `dst=B` 各记录一次；
- 同一反向包可能以 `src=B` 和 `src=A` 各记录一次；
- 记录数不能直接等同于线侧包数或连接数；
- RAW 和 converted PCAP 仍要求逐记录一一对应；
- 只有独立 pktmon 能判断线侧实际目标；
- 外部转换/分析器若按五元组统计，必须预期看到两个逻辑视图。

结构化事件必须使用 `INJECT_CALL_SUCCEEDED/FAILED` 或等价措辞，不得用 `WIRE_SENT`、`DELIVERED_TO_B` 等无法由 WinDivertSend证明的词。

### 21.11 操作 profile 与完整落地阻碍

#### 21.11.1 单一静态审核 profile

v1 只交付一个预先审核的进程映像、A、B和端口保持合同，不实现运行时任意选择样本的交互界面。构建前必须取得：

- 最终目标可执行文件；
- 最终规范化路径规则；
- SHA-256、volume serial、file ID；
- 公网 A；
- 私网 B；
- 验收使用的 TCP 端口；
- 目标 VM A/B 双 route和本地源地址快照；
- B sentinel 已监听的外部证据。

若实际业务要求每次对不同样本自动生成规则，需要另行设计 profile 生成、授权、审计和启动顺序；不能在 v1 一键脚本中让用户临时输入路径或哈希。

#### 21.11.2 无害目标/负向客户端

验收包必须包含两个可区分的、源码可审阅的 Windows PE 客户端映像：

- 目标客户端路径/文件身份/哈希匹配；
- 负向客户端协议行为相同，但路径或文件身份明确不匹配；
- 二者都报告自身 PID、创建时间、最终映像路径、local socket和 `getpeername()`；
- 构建来源、源码、二进制哈希和 manifest必须绑定；
- 不依赖把两个脚本都交给同一个 `python.exe` 来证明进程隔离；
- 不自动下载编译器或二进制。

#### 21.11.3 B sentinel

FakeNet-NG 不启动或管理 B sentinel，但一键验收开始前必须只读探测审核端口并记录 nonce 协议版本。探测失败直接生成明文日志并退出，不改 DNS、不打开 WinDivert。探测仅证明当时端口可达，不作为运行时 fallback或持续健康保证。

#### 21.11.4 A 路由与泄漏证据

目标 VM 必须具有能让 Windows 产生 A-bound SYN 的审核 route。验收同时使用 pktmon证明：

- handle健康期间，目标客户端没有任何线侧 A 包；
- 正向线侧目标是 B；
- B 返回包进入 VM；
- 受控停止前目标客户端已经退出；
- 停止后不再有该 PID/创建时间对应进程，因此不把 handle关闭后的无流量误解为持久 kill-switch能力。

### 21.12 fallback 与兼容性透传的最终声明

v1 仍未添加以下运行时 fallback：

- B失败后直连 A；
- owner失败后按端口、PID-only、basename或命令行猜测；
- route失败后切换其他接口、启用 weak-host或执行源地址 NAT；
- 失败后进入 takeover、默认 FakeNet listener或其他私网目标；
- 自动升级 WinDivert、改Windows Firewall或启动宿主机服务。

v1 明确存在但不属于目标切换 fallback 的两个兼容性透传：

1. `RESOLVED` 为明确非目标进程后继续现有策略；
2. 完全不属于映射/墓碑的 B 入站包原样重注入。

二者均必须被独立测试和第三方审核。目标流量、未知 owner、映射冲突、route漂移和预算耗尽仍失败关闭。

另需明确：WinDivert handle关闭后 Windows恢复正常网络路径是平台生命周期事实，不是 v1 主动提供的 fallback；因此 v1 的“不访问 A”保证只覆盖 handle健康存活期间。要求跨进程崩溃持续阻断必须另立方案。

### 21.13 v1 更新后的第三方审核重点

在 v0 第18节基础上新增最高优先级审核项：

1. A/B 的 BestSource和interface是否完全相同，首次 SYN 冻结及返回方向复核 SubIfIdx 是否充分；
2. 是否完全拒绝源地址 NAT、跨网卡发送和weak-host依赖；
3. FakeNet受控停止前目标进程退出合同是否可操作；对强制终止后的公网泄漏边界是否如实披露；
4. owner查询预算、SYN洪泛和单接收线程饥饿是否会破坏DeepSeek及其他现有机制；
5. owner PID的context-bind语义、socket复制和共享运行时限制是否会使“某进程”身份不成立；
6. 深模块 `prepare/commit/abort` 是否保证 exactly-once、异常回滚和内部状态 locality；
7. 严格 resolver是否与旧best-effort日志interface隔离；
8. 未修改B入站透传是否与目标VM现有WFP驱动形成循环；
9. 全TCP端口映射是否使目标进程接触B上的管理/文件共享服务，项目负责人是否明确接受；
10. 墓碑、idle、half-close和hard timeout是否有VM实测依据；
11. PCAP是否被正确描述为改写前后策略视图，而不是线侧单包证据；
12. 单一静态profile、两个独立PE客户端和外部B sentinel是否真实可获得；
13. owner未知时阻断整个A是否会影响与允许域名动态IP重叠的正常分析工具；
14. 是否存在任何实现者为了通过验收而关闭EDR/VPN、修改firewall/route或降低身份匹配的行为。

### 21.14 v1 替代与保留摘要

v1 替代 v0 的以下内容：

- 总体风险“高”改为“严重、可行性待门禁”；
- B单route验证改为A/B双route、同源/同接口、逐流SubIfIdx及weak-host验证；
- owner `MATCH/NO_MATCH`改为`RESOLVED/NOT_FOUND/AMBIGUOUS/ERROR`；
- 100次首SYN门禁改为多启动、万流、并发、洪泛和现有策略回归；
- `classify_outbound(owner_result)`改为注入resolver的`prepare/commit/abort`事务interface；
- 固定60秒墓碑和未经证明的timeout降为待VM证据/审核数值；
- “绝不回退A”增加WinDivert handle健康存活的时间边界；
- “无fallback”增加两个兼容性透传的明确分类；
- 增加全端口B服务暴露、共享运行时、WFP共存和PCAP双视图风险。

v1 保留：Windows-only、TCP-only、单规则、A为公网全局单播、B为RFC1918、全TCP端口保持、无端口转换、不管理宿主机监听器、不实现Linux、不运行宿主机FakeNet、审核通过前禁止实施。

## 22. v1 内部自评修订与结论

### 22.1 自评发现并已在 v1 内修正的内容

#### 22.1.1 SubIfIdx 不能作为 route API 启动字段

内部自评确认：A/B route preflight 能冻结最佳源地址和 interface index，但不能把 WinDivert `SubIfIdx` 当作 route 查询的固有字段。§21.1 已修正为：启动比较 A/B 源地址和接口；首次目标 SYN 从实际 WinDivert packet冻结 `SubIfIdx`到该映射；返回方向必须匹配映射值。不得伪造或从 route 输出推断 SubIfIdx。

#### 22.1.2 目标进程必须夹在 FakeNet 健康生命周期内

为了减少 handle打开前和受控关闭后的 A 泄漏，正式操作顺序固定为：

```text
目标审核文件已就位，但目标进程未运行
    -> 启动FakeNet并等待PROCESS_REDIRECT_READY
    -> 启动目标进程
    -> 停止并确认目标进程已退出
    -> 停止FakeNet并恢复网络
```

启动 preflight 必须枚举审核映像身份对应的现存进程和发往 A 的现存 TCP row。发现目标进程已经运行或存在目标 A row 时拒绝进入 READY。该检查不能消除检查后启动的竞态，因此一键 runner必须拥有启动目标客户端的动作；正式样本必须由操作者/上层沙箱遵守 READY 后启动合同。

已经存在但没有 NAT 映射的 A 流量全部丢弃：包括 ACK、payload、FIN、RST和非新 SYN。v1 不接管启动前建立的连接，也不让它继续进入域名或公网放行路径。

#### 22.1.3 packet interface 必须包含完整裁决字段

`ProcessRedirectEngine.prepare()` 接受的不可变 packet tuple至少包含：

```text
direction, ipv4_version, fragmented
protocol, tcp_flags
source_ipv4, source_port
target_ipv4, target_port
interface_index, subinterface_index
```

调用方不得只传五元组后在模块外判断 SYN、方向或分片。这样 engine interface 自身能够执行完整授权和状态转换。

#### 22.1.4 分片必须进入失败关闭路径

v1 不支持 IPv4 fragment：

- 出站只要 `dst=A` 且 IPv4 `MF=1` 或 fragment offset非零，无论能否解析TCP端口都丢弃；
- 入站只要 `src=B`、`dst=FrozenLocalIPv4`且是分片就丢弃；
- 入站 WinDivert filter必须覆盖“TCP或IPv4分片”，不能因非首片没有TCP header而绕过；
- filter的具体1.1.8语法必须通过`WinDivertHelperCheckFilter/EvalFilter`和VM抓包验证；
- 分片拒绝事件限速汇总，不进入owner查询。

#### 22.1.5 出站重注入也要做循环门禁

除§21.9的未修改B入站透传外，还必须证明改写后的出站 `L -> B` 包不会再次进入同一个FakeNet handle造成重复裁决；验证覆盖相同priority、其他WinDivert handle和目标VM现有WFP驱动。

### 22.2 v1 固定的容量和时间初值

为避免“实施后再决定关键数值”造成审核循环，v1 给出可审核的保守初值。第三方如要求改变任一安全相关数值，方案必须升版，不能由实现者自行调整。

| 项目 | v1初值 | 失败行为 |
|---|---:|---|
| owner query持续预算 | 32次/秒 | 超预算A新SYN直接丢弃 |
| owner query突发容量 | 16次 | 超预算不排队 |
| 同SYN查询结果缓存 | 3秒，最多4096项 | 满载时拒绝新项，不驱逐活动映射 |
| 进程身份缓存 | 5秒，最多256项 | 未命中重新严格查询；查询预算仍适用 |
| pending事务 | 最多128项，2秒 | 满载/过期时abort并丢包 |
| 活动映射总量 | 1024 | 新流丢弃 |
| 单PID活动映射 | 256 | 该PID新流丢弃 |
| 空闲超时 | 1800秒 | 关闭映射并进入墓碑 |
| half-close超时 | 120秒 | 关闭映射并进入墓碑 |
| hard timeout | 不启用 | 依靠容量和空闲超时保持有界 |
| 正常关闭/端口复用墓碑 | 240秒 | 同完整正反向元组新流丢弃 |
| 注入调用失败墓碑 | 3秒 | 同元组短时失败关闭后允许重新建流 |

说明：

- 32次/秒是安全上限，不是性能承诺；超过该新建速率时连接会被丢弃而不是排队或访问A；
- 墓碑按完整正反向元组建立，不以裸客户端端点封锁其他远端；
- 活动流每个成功处理的有效方向包刷新 `last_seen`；
- timeout必须使用注入的单调clock；系统时间跳变不得提前或延后清理；
- 压力验收若证明这些初值无法满足安全或现有机制回归，停止并升版，不得在交付包中静默调大。

### 22.3 prepare/commit/abort内部事务补充

- `prepare()` 内部不得在持有NAT状态锁时调用Windows owner resolver、文件哈希或route查询；
- engine先在锁内建立有界查询reservation，释放锁后调用adapter，再重新加锁验证reservation、generation和当前快照；
- 在`prepare()`内部发生resolver异常时，由engine自行撤销reservation；调用方不会拿到需要abort的token；
- 调用方拿到token后，任何PCAP写入、packet setter、checksum或WinDivertSend异常都必须调用abort；
- 单receiver线程下也必须按未来并发安全实现，不能依赖“目前不会有SYN/ACK抢在commit前到达”作为interface隐含条件；
- commit失败不得重复发送 packet；应关闭/挂起相关generation并让当前包失败关闭；
- engine.close必须等待/撤销所有reservation和pending token，但不能等待Windows owner API无限返回。

### 22.4 验收客户端的可交付性

两个无害PE客户端必须在交付包构建前离线生成，VM内不编译：

- 仓库保留源代码和确定性构建命令；
- 交付包包含审核后的x64二进制；
- manifest内记录哈希，不生成单独`.sha256`文件；
- 目标和负向客户端使用不同最终路径/文件身份；
- 两者协议、连接A、nonce校验和`getpeername()`逻辑保持相同；
- 如果无法提供可复核二进制或目标VM拦截其运行，动态验收阻断。

### 22.5 分阶段授权边界

尽管§22.2已固定初值，首SYN owner稳定性和同源/同接口拓扑仍不能在宿主机静态证明。第三方审核通过并由项目负责人批准后，实施顺序分为两个门阶段：

1. **Phase A：** 只实现/运行VM技术门禁、route/weak-host只读预检、严格owner resolver诊断和无害客户端；不得接入正式数据包改写；
2. 分析Phase A明文日志；若任何可行性门禁失败，停止并升版方案；
3. Phase A全部通过后，可在同一已审核v1合同下继续正式`ProcessRedirectEngine`和Windows改写实现；
4. 正式实现完成后仍必须执行完整VM验收，不能用Phase A替代。

Phase A不是fallback，而是审核后实施的第一阻断门禁。它不会在宿主机运行FakeNet-NG，不会修改正式裁决，不会授权驱动升级、Firewall、WFP、源地址NAT或其他范围变化。

### 23.0 修订范围与状态

v2 对 `2026.08.06-02-审计-Windows按进程透明重定向公网IPv4至私网IPv4方案.md` 的意见逐项进行了代码交叉核对。v2 只修订方案，不修改生产代码、配置、测试程序或交付包，也不得在当前宿主机运行 FakeNet-NG。

### 23.1 WinDivert 有效运行时基线与依赖来源

审计 M1 的核心事实成立：锁定的 `pydivert==2.1.0` wheel 自带 WinDivert 1.3.0，包内代码从 `pydivert/windivert_dll` 计算 DLL 路径，并使用服务名 `WinDivert1.3`。因此，旧文所有把 **1.1.8** 当作已知有效运行时基线的表述均由下列合同取代：

1. 源码/wheel 运行方式的预期基线是 `pydivert==2.1.0` 自带 WinDivert 1.3.0；
2. 仓库 `windivert/` 仍有另一套 1.1.x 二进制，`fakenet.spec` 还会把它们加入冻结产物；仅凭源码导入路径不能证明每种冻结产物最终加载哪一套二进制；
3. Phase A 必须在目标 VM 和实际交付形态中记录：是否 frozen、`pydivert.windivert_dll.__file__`、其解析后的 `DLL_PATH`、加载模块路径、DLL/SYS 文件版本和 SHA-256、交付包内两套二进制清单，以及 `sc query WinDivert1.3` 的结果；
4. manifest 必须把“预期版本”和“实测加载版本”分开记录。二者不一致、路径不可定位、存在同名歧义或服务状态无法归因时，Phase A 失败并停止实施；
5. 首 SYN owner、filter 语法、重注入和驱动升级判断一律以 Phase A 证明的有效运行时为准。若证据确认 1.3.0，则后续所有门禁以 1.3.0 为基线；不得再按 1.1.8 推断；
6. 清理仓库 `windivert/` 或调整 `fakenet.spec` 不属于本功能方案，未经单独影响分析不得顺带删除。v2 只消除版本认知歧义。

### 23.2 裁决链位置：新增互斥分支，不重排既有机制

现有出站机制的相对顺序保持不变：

```text
control permit
-> relay return fixup
-> takeover sink
-> domain relay forward / new SYN
-> reviewed IPv4
-> FakeNet diversion / final drop
```

启用本功能后，只在 `relay return fixup` 与 `takeover sink` 之间插入新的进程重定向分支：

```text
control permit
-> relay return fixup
-> process redirect for exact A
-> takeover sink
-> domain relay forward / new SYN
-> reviewed IPv4
-> FakeNet diversion / final drop
```

这不会改变任何两个既有机制之间的先后关系，不能表述为“把 takeover 相对现有机制重排”。`A` 必须是公网全局单播 IPv4；takeover sink 必须是 RFC1918 私网 IPv4；并且 `B == takeover_ipv4` 被启动校验禁止，三者在合法配置中不重叠。

回归测试必须显式覆盖：目标进程访问 `A` 只进入 process redirect；明确非目标进程访问 `A` 不会被 takeover 误捕；访问真实 takeover 地址仍由 takeover 捕获；非法地址重叠在打开 WinDivert 前拒绝启动。

### 23.3 非目标进程兼容性透传的精确可达条件

审计 M3 对 domain relay 条件的澄清成立。owner 明确解析为非目标进程时，是“继续既有剩余裁决链”，而不是保证进入 domain relay：

1. 仅当 `A` 存在仍有效的允许域名 DNS lease，且目的端口为 `443` 时，才可进入 domain TLS relay；
2. `A` 无 lease 或目的端口不是 `443` 时，relay 不匹配，继续进入后续 reviewed IPv4 / FakeNet diversion / final drop；
3. 但合法配置已禁止 `A` 出现在 `ExternalAllowedIPv4Rules` 中，所以针对 `A` 的 reviewed IPv4 分支在本功能启用时不可达；不得为测试制造一个启动合同明确拒绝的配置；
4. owner 为 `NOT_FOUND`、`AMBIGUOUS`、`ERROR` 或预算耗尽时仍立即丢弃；这会阻断本来可能命中有效 443 lease 的正常工具流量，是已接受的失败关闭可用性代价；
5. “兼容性透传”只承诺继续既有裁决，不承诺连接成功，也不承诺一定进入 relay。

新增自动测试：

- `A` 无 lease、非目标进程、非 443：不进 relay、不进 process redirect，按现有 diversion/drop 裁决；
- `A` 有有效 443 lease、owner 明确为非目标：进入 domain relay；
- `A` 有有效 443 lease、owner 未决：失败关闭，不进入 relay；
- `A` 与 reviewed IPv4 静态规则重叠：启动前拒绝，而不是运行期测试其优先级。

### 23.4 fallback 与预算耗尽

审计确认旧文没有隐藏的运行时目标切换 fallback，v2 保持该结论。进一步明确：

- owner 查询预算耗尽是**失败关闭**，不是 fallback；该 SYN 直接丢弃，不排队，不继续 domain relay、reviewed IPv4、真实 `A` 或其他目标；
- owner 明确为非目标后继续既有裁决链，以及未映射/非墓碑 `B` 入站包原样重注入，仍属于两个明确披露的兼容性透传；
- WinDivert handle 关闭后的 Windows 正常网络路径仍是平台生命周期边界，不是本功能主动提供的 fallback。

v2 没有新增任何未经请求的 fallback。

### 23.5 owner 身份二次复核的语义和时机

接受 R1 指出的 TOCTOU 澄清需求，但不把 Windows API 调用放到发送后的 `commit()`：

1. 针对一个新 SYN，只执行一次 `GetExtendedTcpTable` owner-row 枚举和完整元组归属解析；
2. `prepare()` 在锁内建立 reservation，释放状态锁后执行 owner 查询与身份解析；
3. 重新取得状态锁并确认 generation、reservation、route 和容量仍有效后，在返回可发送 decision/token **之前**，通过有界的进程 handle 查询重新核对 PID 创建时间、最终映像路径和文件身份；这不是第二次 TCP owner table 枚举；
4. 复核失败、进程退出、PID 重用、最终路径/文件身份变化或查询超时，均撤销 reservation 并失败关闭；
5. 冻结审核文件 handle 继续作为启动时 SHA-256/文件身份基准；热路径不得无界重复读取或哈希整个文件；
6. `commit()` 只处理已经成功注入后的内存状态转换，不查询 Windows owner/process API。发送后的 `commit()` 才去发现身份变化已经太晚，也会破坏事务接口的 locality。

对应故障测试必须覆盖 owner 查询后立即退出、PID 重用模拟、文件替换尝试、进程 handle 拒绝访问和复核超时。

### 23.6 WinDivert 过滤器与 IPv4 分片

R2 成立。旧文 `inbound and ip and tcp ...` 不能作为覆盖非首片的最终合同，因为缺失 TCP header 时 `tcp` 测试可能为 false。v2 使用 IPv4 header 的协议字段选择 TCP 协议号，候选精确分支为：

```text
outbound and ip and ip.DstAddr == A and ip.Protocol == 6
inbound and ip and ip.SrcAddr == B and ip.DstAddr == FrozenLocalIPv4 and ip.Protocol == 6
```

实现时将这两个分支与现有 filter 以括号明确的 `or` 合并。`ip.Protocol == 6` 不依赖 TCP header，必须捕获首片、`MF=1` 片和 offset 非零的非首片。捕获后，只要出站 `dst=A` 或入站 `src=B,dst=FrozenLocalIPv4` 的 IPv4 fragment bits 非零，就在解析 TCP 端口、owner 查询或 NAT 查表之前失败关闭。

Phase A 必须使用实际加载 DLL 的 `WinDivertHelperCheckFilter`/`WinDivertHelperEvalFilter` 验证最终展开 filter，并用首片、非首片、乱序片、重叠片及正常未分片 TCP 的真实包语料验证。语法不被有效运行时接受或任一非首片未被捕获时，Phase A 阻断，不得退回 `tcp` 关键字或放行分片。

现有 `classify_reviewed_ipv4_fragment` 的原始字节解析和失败关闭模式可以复用，但它当前只按出站目标地址查 `target_protocols`。实施必须把它泛化为方向感知的守卫，分别处理 `dst=A` 和 `src=B,dst=L`；不得把“已有 helper”误当作 B 入站路径已经存在。

### 23.7 容量口径与 owner 查询性能

R3 的自我修正结论纳入合同：

- 活动映射总量 1024，统计所有命中本规则 `A` 的活动映射；
- 单 PID 256，只统计该 PID 对 `A` 的活动映射，不统计该进程的其他连接；
- 多个同时运行且身份均匹配审核映像的 PID 共享 1024 总量，每个 PID 分别受 256 限额；
- Phase A 必须覆盖多个目标进程实例、单 PID 逼近 256 和多 PID 逼近 1024 的边界。

O2 的代码事实也纳入披露：legacy `handle_pkt` 路径会按包调用现有 `get_pid_comm`。但在 `DomainAllowList` 策略路径中，control/takeover/relay/reviewed 等短路流量并不都进入 legacy `handle_pkt`，所以严格 resolver 对 `A` 的新 SYN 仍可能是新增成本，不能据此宣称“单流成本相当或更低”。性能验收必须分别记录 legacy diverted 基线、启用但不命中 `A`、命中 `A`、SYN 洪泛四组数据；查询预算和接收线程饥饿门禁保留。

### 23.8 B sentinel 只读探测约束

接受 R4：一键验收须先取得并冻结 A/B route 快照，再从 `FrozenLocalIPv4` 显式 bind 探测 socket，并只读核对该目标的最佳 route/interface index 与 `FrozenInterfaceIndex` 一致。bind 失败、有效 route/interface 不一致或 nonce 协议不匹配时，在修改 DNS和打开 WinDivert 前退出。

探测仅证明该时刻该审核端口的可达性，不约束运行时允许端口、不持续监控 B 服务，也不构成 B 不可达时的 fallback。

### 23.9 全端口暴露与 takeover 的关系

现有 takeover sink 同样不按 `ExternalTakeoverProbeTCPPorts` 限制运行时目的端口；该配置只用于启动前探测。这一事实应在实现注释、README和验收日志中披露。

但本功能仍新增“审核进程访问公网 `A:any` 会被导向私网 `B:any`”的授权路径，`B` 还被明确禁止等于 takeover 地址。因此，既有 takeover 的风险接受不能自动替代本功能的显式风险接受。全端口合同和风险门禁保持不变；不得因两者性质相似而降低风险等级，也不得把 probe 端口误写成运行时端口限制。

### 23.10 规则冲突和现有机制复用边界

1. 实现可以复用 `_parse_reviewed_ipv4_rules` 返回的 reviewed 地址集合，对 `A in reviewed_set` 做新的跨功能启动冲突检查；
2. 现有 `_parse_reviewed_ipv4_rules` 的 protected-address 检查只保证 reviewed 规则不等于 takeover/DNS/local 地址，并不会自动检查新 process-redirect 的 `A/B`；
3. `B == takeover_ipv4` 必须由新的集中式 process-redirect 冲突校验显式拒绝，不能声称现有 reviewed 规则检查已经“对称覆盖”；
4. `A` 公网、`B` RFC1918、takeover RFC1918、local/DNS/reviewed 的全部互斥关系应集中返回结构化错误并在打开 WinDivert 前完成；
5. 分片处理复用现有原始 IPv4 解析模式，但需要方向感知扩展，风险仍由 R2 的 Phase A 门禁承担。

### 23.11 v2 新增/修订审核重点

第三方复审除 v1 原有重点外，必须重点检查：
